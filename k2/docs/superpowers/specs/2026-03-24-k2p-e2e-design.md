# k2p End-to-End Design — URL, Signal Server, Home, Away, Security

> **Revision 2**: Fixed 5 BLOCKERs from spec review (B1-B5, W2, W3).

## Overview

k2p enables users to run a "k2s at home" — a proxy node behind NAT, discoverable via a signal server, reachable via hole punching (direct) or relay (fallback). The data plane is k2v5 (QUIC + k2cc). k2s acts as the signal/relay server but is zero-trust: it cannot read traffic or impersonate peers.

## Roles

| Role | What it is | Analogy |
|------|-----------|---------|
| **Home** | Node behind NAT, runs ProxyHandler, serves traffic to its LAN | A k2s behind NAT |
| **Away** | Client connecting to Home from anywhere | A k2 client |
| **k2s** | Signal server + stub relay, zero-trust | Tailscale DERP |

## UDID Format

UDIDs are constrained to `[a-z0-9][a-z0-9-]*[a-z0-9]` (lowercase alphanumeric + hyphens, no dots, no leading/trailing hyphens, min 3 chars, max 32 chars). This ensures safe use as DNS subdomain labels.

Validation: `regexp.MustCompile("^[a-z0-9][a-z0-9-]{1,30}[a-z0-9]$")`

## k2p URL Format

```
k2p://home-abc:PEER_SECRET@home-abc.proxy.kaitu.io:443?pin=sha256:xxxx&ip=1.1.1.1&ip6=xxxx&ech=xxxx&fp=chrome
      ────────  ───────────  ──────────────────────────  ─────────────  ─────────────────────────────────────
      UDID      peer secret  signal server (UDID prefix)  Home cert pin  inherited from k2v5 (k2s params)
```

### Fields

| Field | Source | Purpose |
|-------|--------|---------|
| `home-abc` | userinfo username | Home's UDID (validated against UDID format) |
| `PEER_SECRET` | userinfo password | Peer auth (Home generates locally, k2s never sees) |
| `home-abc.proxy.kaitu.io` | host | Signal server domain (UDID as first subdomain label) |
| `443` | port | k2s port (signal + relay), default 443 |
| `pin=sha256:xxxx` | query | Home's TLS cert pin hash (Away verifies Home identity) |
| `ip=1.1.1.1` | query | k2s IP (skip DNS, same as k2v5) |
| `ip6=xxxx` | query | k2s IPv6 (same as k2v5) |
| `ech=xxxx` | query | k2s ECH config (for signal/relay connection to k2s) |
| `fp=chrome` | query | TLS fingerprint (for signal/relay connection to k2s) |

### Parsing

`k2p.ParseURL(raw string) (k2p.Config, error)`:
- Scheme must be `k2p`
- `Config.HomeUDID` = username (validated against UDID format)
- `Config.PeerSecret` = password (must be non-empty)
- `Config.SignalServer` = `https://{base-domain}:{port}` where base-domain = host with first label (UDID) stripped. E.g. `home-abc.proxy.kaitu.io` → `proxy.kaitu.io`
- `Config.Pin` = pin query param
- `Config.WireCfg` = wire.Config populated from ip/ip6/ech/fp/port (reuse wire.ParseURL logic for query params)

### URL Generation (BuildURL)

`k2p.BuildURL(udid, secret, k2sHost string, port int, pinHash string, k2v5Params url.Values) string`

## Signal Server (`signal/` package)

Independent package. Dependencies: stdlib + `github.com/gorilla/websocket` + `github.com/sasha-s/go-deadlock`.

### Store

```go

    mu    deadlock.RWMutex     // per CLAUDE.md concurrency rules
```

k2s does NOT store: peer secret, pin hash, TLS private key.

### Registration Auth (prevents UDID hijack)

Problem: without auth, anyone who knows a UDID can overwrite Home's registration.

Solution: **registration token**. Flow:
1. Home runs `k2 peer setup` → contacts k2s → `POST /k2p/claim {udid}` → k2s returns `{reg_token}` (one-time)
2. Home stores `reg_token` locally
3. All subsequent `POST /k2p/register` requests include `Authorization: Bearer {reg_token}`
4. k2s validates: `hash(reg_token) == stored_hash` → accept update. Mismatch → 403.
5. First claim wins: if UDID already has a reg_token, new claims are rejected.

This prevents UDID hijack: attacker doesn't know the reg_token, can't overwrite Home's entry.

### HTTP+WS Endpoints

| Method | Path | Purpose | Auth |
|--------|------|---------|------|
| `POST` | `/k2p/claim` | Home claims UDID (first-time) | None (first-come) |
| `POST` | `/k2p/register` | Home updates address/networks | `Bearer {reg_token}` |
| `GET` | `/k2p/lookup/{udid}` | Away queries Home's info | None (public) |
| `POST` | `/k2p/connect` | Away signals punch request | None |
| `GET` | `/k2p/ws?udid={udid}` | Home persistent WS | `Bearer {reg_token}` in query |
| `GET` | `/k2p/relay?udid={udid}&peer={peer}` | Relay WS (both sides) | UDID in query |

### Stub Relay

When punch fails, both Away and Home open WebSocket connections to k2s relay endpoint. k2s matches by UDID and forwards bytes.

```
Away WS ←→ k2s relay ←→ Home WS
           (binary messages, no parsing)
```

Protocol:
- WebSocket **binary messages** (opcode 0x02), NOT text/JSON
- Each WS message = one UDP datagram (preserves packet boundaries)
- k2s matches relay pairs by UDID, forwards message bytes unchanged
- Inner QUIC (Away↔Home, Home's TLS cert) runs on top
- k2s sees only encrypted QUIC packets

```
// Away opens: GET /k2p/relay?udid=home-abc&peer=away-xyz
// Home opens: GET /k2p/relay?udid=home-abc&peer=home-abc
// k2s: when both connected, forward binary messages between them
```

## Peer Authentication Protocol

After QUIC handshake (Away verified Home's cert via pin), Away must prove it knows PEER_SECRET.

Protocol: Away opens the **first QUIC stream** (stream ID 0) and sends a peer auth frame:

```
// Peer auth frame (sent by Away on first stream)
[1 byte: version = 0x01]
[2 bytes: secret length (big-endian)]
[N bytes: PEER_SECRET (UTF-8)]
```

Home reads the first stream, extracts PEER_SECRET, compares with stored hash:
- Match → writes `[1 byte: 0x00]` (success), keeps QUIC connection alive
- Mismatch → writes `[1 byte: 0x01]` (rejected), closes QUIC connection

After auth success, subsequent streams use standard k2v5 framing (StreamHeader + StreamResponse).

This is simpler than k2v5's JWT+ticket flow — k2p is peer-to-peer with a pre-shared secret, no token rotation needed.

## Home Side

### `k2 peer setup`

```
$ k2 peer setup k2v5://user:pass@proxy.kaitu.io:443?ech=xxx&ip=1.1.1.1
  请设置 peer 密码: ********
  UDID (留空自动生成): home-abc

  ✓ 生成 TLS 证书 (EC P-256)
  ✓ 注册到 proxy.kaitu.io (UDID: home-abc)
  ✓ 检测内网: 192.168.1.0/24, DNS: 192.168.1.1

  你的 k2p 链接:
  k2p://home-abc:PASSWORD@home-abc.proxy.kaitu.io:443?pin=sha256:xxxx&ip=1.1.1.1&ech=xxx

  把这个链接发给需要访问你家网络的人。
  配置已保存到 ~/.k2p/
```

Steps:
1. Parse k2v5 URL → get k2s params (host, port, ip, ech, fp)
2. Generate or accept UDID (validate format `[a-z0-9-]`)
3. Prompt password → PEER_SECRET (hash with bcrypt for storage)
4. `wire.GenerateCertPair()` → TLS cert + pin hash via `CertPair.FormatPins()`
5. Detect local networks: `net.Interfaces()` → filter private CIDRs
6. Claim UDID: `POST /k2p/claim {udid}` → get reg_token
7. Register: `POST /k2p/register` with Bearer reg_token
8. Save to `~/.k2p/config.json`: {udid, reg_token, cert_path, secret_hash}
9. Print k2p URL (with BuildURL)

### `k2 peer run`

```
$ k2 peer run
```

Flow:
1. Load `~/.k2p/config.json` (UDID, reg_token, cert, secret_hash)
2. STUN probe → discover public address
3. Register with k2s signal (Bearer reg_token)
4. Open WS to k2s for notifications (Bearer reg_token)
5. Keepalive loop (re-STUN + re-register every 25s)
6. On PunchNotify → punch → QUIC listen → peer auth → ProxyHandler

ProxyHandler config:
- `AllowPrivateIP = true` (verified: field exists at server/handler.go:96)
- Peer auth on first stream before accepting traffic streams

### Auto-detect Networks

```go
func detectPrivateNetworks() ([]string, string) {
    ifaces, _ := net.Interfaces()
    var cidrs []string
    var dns string
    for _, iface := range ifaces {
        if iface.Flags&net.FlagUp == 0 || iface.Flags&net.FlagLoopback != 0 {
            continue
        }
        addrs, _ := iface.Addrs()
        for _, addr := range addrs {
            if ipnet, ok := addr.(*net.IPNet); ok && ipnet.IP.IsPrivate() {
                cidrs = append(cidrs, ipnet.String())
                // Use gateway (first IP in subnet) as DNS candidate
                if dns == "" {
                    gw := make(net.IP, len(ipnet.IP))
                    copy(gw, ipnet.IP)
                    gw[len(gw)-1] = 1
                    dns = gw.String()
                }
            }
        }
    }
    return cidrs, dns
}
```

## Away Side

### Connection Flow

```
Away parses k2p URL
  │
  ├── 1. Extract signal server (strip UDID prefix from host)
  ├── 2. Lookup Home: GET /k2p/lookup/{udid}
  │      → addr, nat_type, networks, dns
  ├── 3. STUN probe → classify own NAT
  ├── 4. Signal connect: POST /k2p/connect {away_addr, nat_type}
  ├── 5. Punch (standard or birthday)
  │      ├── success → step 6
  │      └── fail → open relay WS, inner QUIC over WS → step 6
  ├── 6. QUIC handshake (verify pin=Home cert hash)
  ├── 7. Peer auth: open stream 0, send PEER_SECRET
  │      ├── accepted → step 8
  │      └── rejected → error "peer auth failed"
  ├── 8. Return wire.Dialer (standard k2v5 interface)
  └── 9. Auto-configure: route networks through k2p Dialer
```

## Security Model

### Credential Separation

| Credential | Home | Away | k2s | Purpose |
|-----------|------|------|-----|---------|
| UDID | ✅ | ✅ | ✅ | Signal routing (public) |
| reg_token | ✅ | ❌ | ✅ (hash) | Registration auth (prevent hijack) |
| PEER_SECRET | ✅ (hash) | ✅ | ❌ | Peer authentication |
| TLS private key | ✅ | ❌ | ❌ | TLS handshake |
| pin (cert hash) | ✅ | ✅ | ❌ | Verify Home identity |

### Attack Resistance

| Attack | Prevented by |
|--------|-------------|
| k2s reads traffic | End-to-end QUIC encryption (Home's TLS cert) |
| k2s impersonates Home | Away verifies pin (cert hash in URL) |
| k2s impersonates Away | Home verifies PEER_SECRET (k2s doesn't know it) |
| k2s injects traffic | Cannot forge inner QUIC packets (no TLS session key) |
| Attacker hijacks UDID registration | reg_token auth on /k2p/register |
| Third party connects to Home | Must know PEER_SECRET + pass pin verification |
| MITM on punch path | QUIC TLS handshake + pin verification |
