# Engine Layer (engine/)

Unified tunnel lifecycle manager — single source of truth for connection state.
Both desktop (daemon/) and appext (appext/) delegate all lifecycle here.

## Architecture

```
Platform Shell (daemon/appext/gateway)
    │
    ├── builds engine.Config (platform-specific fields)
    └── calls engine.Start(cfg)
              │
              ├── 1.  prefetchRulesForStart — local only: rule.SeedFromEmbedIfEmpty, else whatever is on disk (no network on the connect path)
              ├── 1a. missingConfiguredRegions → DIAG: rule-bundle-missing-region + fail 504
              ├── 1b. buildOutboundMap (via URL → rule.Target; 0=direct, 1=reject, 2+=wire) + buildRuleEngine
              ├── 1c. rule-miss telemetry reporter (only if Telemetry.RuleMiss.Enabled)
              ├── 2.5. Start NetworkMonitor (DirectDialer needs DefaultInterface)
              ├── 5. Router (core.NewRouter(ruleEngine))
              ├── 6. Provider (external from gateway / platform FD / proxy / desktop TUN); Start failure → 412
              ├── 6.5. Per-outbound transport setup:
              │      for each unique k2v5:// → ParseURL → resolve → RaceTransport → TM
              │      (parallel via errgroup; first k2v5 route = primaryTM). Only k2v5:// routes get a
              │      transport — a k2subs:// route must be resolved by the shell first
              ├── 7. ClientTunnel
              ├── 8. DNS middleware (TUN/TProxy mode only)
              │      DNS proxy dialer = primaryTM's TCP-WS (control-plane)
              │      Data traffic dialer = per-outbound TransportManager
              ├── 9. Commit → StateConnected + start reRaceLoop / outboundReplaceLoop
              ├── 10. HealthMonitor start (1Hz wire stats + health FSM + echoLoop)
              └── 11. Rule bundle updater (immediate check, then hourly, hot-reload on change; skipped under NetworkExtension)
              QUIC recovery probing during TCP-WS fallback is wire's (`TransportManager.runProbeOnce`), not engine's.
```

## State Machine

5 engine states: `disconnected`, `connecting`, `connected`, `paused`, `reconnecting`
Note: `reconnecting` and `paused` are transient — engine.state stays `connected`, these are handler-only broadcasts

- `Start()`: disconnected → connecting → connected (or disconnected on error)
- `Stop()`: any → disconnected (idempotent, resets `paused`)
- `OnNetworkChanged()`: routes through netCoordinator as SignalChanged → reconnect if network is up
- `OnNetEvent(event)`: routes through netCoordinator — "unavailable" stops probe, "available" triggers doNetworkReconnect, "changed" reconnects if up (appext's `NotifyNetEvent` lands here)
- `Pause()`: connected → paused (releases wire transports via the scoreboard-preserving `ResetConnections`, provider stays alive — iOS memory pressure / every device sleep)
- `Wake()`: paused → connected (forces fresh wire transport connections, scoreboard and channel choice kept)
- `fail()`: any → disconnected + classified error

### Hold (waiting for the user's network) — `hold.go`, `outboundReplaceLoop`

A node that looks dead may only look dead because the user's network is. Before spending replacement candidates the replace loop judges the network (`judgeNet` → `decideNet`: netCoordinator `isNetworkUp` → passive public direct dial 0–10s old via `directTrack` (a negative age = clock stepped back, ignored; **skipped at `pre-exhaust` and on hold / retry ticks (`wait-tick`, `net-event`)**) → active `netChecker` on `ClientConfig.Netcheck`) and logs `DIAG: netcheck`. **Empty netcheck list = `netUnknown` → no gating at all**: the loop behaves as before the verdict existed (Phase B proceeds, exhaustion goes on the retry schedule and fails 503 only at the 10-min cap, 401/402 preserved; no-candidates retries show 503, never 106). Only iface-down (101) can still hold. This is the k2r gateway / CLI / old-webapp path; the webapp always sends targets. (Deviates from spec §4.2 "缺失按情况 2 处理" by controller ruling — a blind hold blocked k2subs rotation and multi-slot re-race on k2r.)

- **When**: `pre-phaseB` (Phase-A streak ≥ `reRaceFailThresholdForReplace`, before `NextURL`) and `pre-exhaust` (provider exhausted). Not between candidates — `pre-exhaust` covers a network that dies mid-failover (always an active probe: fast-failing candidates finish well inside 10s, so a direct dial from before the outage would otherwise vouch for a dead network), and then the provider's exclusions are `Reset()` (they may be innocent) before holding.
- **Hold**: `holdErr` = verdict's 101/106/107 (`setHold`, pushed). `buildStatusLocked` reports `reconnecting + holdErr` while connected and not paused, so every push/poll path (network reconnect, health critical, wake, daemon `status`) shows the hold without per-call-site changes. **A 401/402 `lastError` outranks the hold** (actionable beats "waiting"). Re-judge on backoff `holdBackoff` 5s→10s→30s→30s… (no cap) or immediately on `holdWake` (cap-1 chan poked by `doNetworkReconnect` after its pushes; a wake restarts the backoff; `escalate` drains a stale token before its `pre-phaseB` verdict so a pre-verdict event cannot skip the 5s step). Every wake (`wait-tick` / `net-event`) that is not online also tries one Phase-A (`reason=wait-tick`) on the current node (the verdict can be wrong — netcheck targets filtered on this network while the node answers); success ends the hold (streak reset, connected pushed), a 401/402 fails, anything else keeps holding. Online (or unknown, e.g. iface back up with no targets) → clear hold, one Phase-A on the **current** node, Phase B only if that fails.
- **No candidates** (`ErrNoCandidates`: manual mode / no fallbacks / URL no provider owns): never `fail`, and **never block the loop** (other outbounds keep their Phase A / Phase B). The loop keeps a goroutine-local `retrySet` (target → next time, backoff step) and one armed timer for the earliest entry in its own `select` (`holdTimerFn` + `holdNow`, both injectable). Each attempt (`retryOnce`) = `judgeNet` + one Phase-A and, if that fails on a working network (not user action), one Phase B — on every tick when the node itself is dead/refusing; when its error is a **code-less reject** (node alive, Center unreachable from it) at most once per `codeLessPhaseBEvery` = **2 min** per target (`retrySet.codeLessPhaseBDue`, measured from `retryState.lastPhaseB`, the start of its last tick Phase B, or from joining the schedule when it has had none). Code-less ticks still never count toward the cap. Why both halves: Phase A only (review 3 M-3) pinned a node whose *own* Center path is broken to 503 forever beside a working candidate (sim FB); every tick would cost N handshakes per client for a whole global Center outage. Bound in a global outage: one Phase-B round (≤ N candidate setups) per 2 min, on top of the tick Phase-As (4 per 2 min under 10 min pending, 2 after). Phase B runs with a **Reset** provider (`retryPhaseB`; manual mode → `ErrNoCandidates` at once, harmless; all candidates code-less, **zero candidates tried** (everything still excluded) or any other exhaustion → stays scheduled as exhausted (capped, see below); offline → hold only, no candidates burnt) — so a target scheduled for a Center outage never sits on a node that died since (review B). Success removes the target (streak 0; leaving via Phase-A also Resets the provider, so an outage's exclusions never outlive the schedule — review 3 I-2), failure advances 5s→10s→30s→30s…; any `holdWake` (all pending targets, backoff restarts) attempts at once; **echo signals for a pending target are dropped** (with failing traffic the probe could signal every ~16s and bypass the backoff — review C); 401/402/403 fails. Shown hold while the set is non-empty: 503, or the network verdict's 101/106/107 when offline; cleared when it empties. The loop syncs the hold after every event it handles (this also clears a leftover hold after a Phase-B swap). The network hold, by contrast, still blocks the loop — the network is shared, every outbound is equally affected — and restores the retry set's hold when it ends.
- **After a wait ends successfully** a queued echo re-race signal for the same target (queued during the wait) is dropped (`dropQueuedSignal`) — it would re-race and `ReplacePrimary` over the dialer just installed.
- **Tried nothing** (`exhaustedError.tried == 0`: every candidate still excluded from earlier rounds — k2subs `Manager` exclusions never expire): `escalate` Resets the provider and runs **exactly one** more round; only a second tried-nothing (or a real exhaustion) goes on to the exhaustion schedule below (review 4 concern 4). A tick's Phase-B swap exit also Resets (I-2 residual).
- **Exhausted on a healthy network — no disconnect (R1, 2026-11-05)**: five fix rounds each found another "live nodes but fail(503)" path, because every misread "node dead" became a disconnect. Now an exhaustion (`exhaustedError{tried, userAction, allUserAction, allCodeLess}` — including tried-nothing and all-code-less rounds) goes on the `retrySet` as **exhausted** (`DIAG: outbound-exhausted`, hold `exhaustedHoldError` 503 "…all replacement candidates failed; retrying"; ticks 5→10→30s, `DIAG: transport-rerace reason=exhausted-retry`, each = Phase A then Phase B with Reset; recovery → `DIAG: outbound-exhausted-recovered via=phaseA|failover`). Only `exhaustFailAfter` = **10 min** of continuous online exhaustion fails: `failAtExhaustCap` → `DIAG: outbound-exhausted-fatal` → `failExhausted` = `OnOutboundFatal` (k2r rebuilds on it; the desktop daemon and appext only log / ignore it, so desktop and mobile end disconnected) + `fail(503)` (`outboundExhaustedError`), unless a 401/402 is the cause: a sticky `lastError` 401/402 first, then the last coded verdict a candidate's setup was rejected with. The cap clock (`retryState.since`) restarts when the target leaves the schedule and is cleared by any tick (`exhaustCounts`) whose **latest** verdict blocks failover — the tick-start verdict, or Phase B's `pre-exhaust` one when that blocked (`retryPhaseB` returns it; that tick also shows its 101/106/107 — review I-1) — so offline never counts; or whose Phase A is code-less; or whose round had **any** code-less candidate answer (`exhaustedError.anyCodeLess`, sim FA: a round counts only when the current node's Phase A and every candidate setup failed at transport — mixed rounds are routine in an outage now that code-less ticks run Phase B every 2 min; `allCodeLess` still drives the exhaustion-time Reset). Code-less = node alive, Center down: a Center outage of any length never disconnects, even with the current node dead (review C1 / M-2 ruling); a dead fleet (transport failures) caps. Manual mode / `ErrNoCandidates`: no cap, as before — except a `fromShell` target (see Providers). **Account verdicts still fail at once** (`failIfExhaustedByAccount` → `failIfUserAction`): a sticky 401/402, or *every* candidate tried rejected with a coded 401/402/403 (a mix with dead candidates is scheduled; the cap then reports the code). The loop's only session-ending exits are `failIfUserAction` and `failAtExhaustCap` — `TestReplaceLoopFailSitesAllowList` (AST, engine non-test files) allow-lists, by receiver-qualified function (`Engine.X`; closures never allowed; a fail-ish name on anything but the method's own `*Engine` receiver is a violation), every reference to `e.fail` (`Start`, `failIfUserAction`, `failExhausted`), `failExhausted` (← `failAtExhaustCap` only), `OnOutboundFatal` (`failIfUserAction`, `failExhausted`), callers of `failIfUserAction` / `failIfExhaustedByAccount`, and `e.Stop` / `e.cancel` / `e.reRaceCancel` (`Start` / `Stop` / `fail` only). Every engine race ctx is `raceCtxTimeout` = `wire.RaceWorstCase()` (14.6s) + 1s (`TestRaceCtxOutlivesWireWorstCase`). **Replace-loop user-action verdict is `replaceLoopUserAction` (`replace_verdict.go`), not `ClassifyError`**: only an explicitly coded metadata reject 401/402/403 (403 = device class / ban / brand mismatch) or a ClassifyError user-action from elsewhere (k2subs fetch) counts; the **code-less** legacy reject (k2s `unauthorized` when Center is unreachable) — and equally `wire.ErrMetadataTimeout` (handshake done, verdict never came: Center hanging, PVE S15; `ClassifyError` → 503, never 401) — is a server-side transient — keep re-racing / rotating, and if every candidate tried answered code-less (the current node's own error does not matter — it may be dead), the exclusions are Reset at exhaustion, which goes on the retry schedule like any other; its ticks re-run Phase A then Phase B, so it recovers on the current node or a candidate once auth works. `ClassifyError`'s initial-connect mapping (code-less → 401) is unchanged. A candidate's coded 401/402/403 is remembered and outranks 503 at exhaustion. A 401/402/403 Phase-A rejection still fails immediately, before any judgement — on the **first** Phase-A, not after `reRaceFailThresholdForReplace` (PVE S8: waiting for the streak cost a second ~48s strike cycle); `TestReplaceLoop_FirstPhaseAUserActionFailsImmediately`. A successful Phase-A or Phase-B swap `ClearWireError()`s a stale non-user-action `lastError` (`ClearWireError` is a no-op unless state is connected — a clear racing `fail()` must not erase the final error); core's `wireOutbound` drops `ReportWireError` from a dial whose transport was swapped out mid-dial (`wire.CurrentDialer`).
- **Ownership / timing**: only the replace loop writes `holdErr` (plus `Stop`/`fail`, which clear it). `setHold` is a no-op once the loop's ctx is cancelled or state ≠ connected, so a late write never lands on the next session. The hold `select`s on ctx, so `Stop` ends it immediately; in-flight netcheck HTTP is ctx-bound. Clock is injectable (`Engine.holdTimerFn`); `failover_test.go` drives everything with fakes.
- **Providers**: `Start` always installs `newCompositeProvider(newStaticProvider(Fallbacks), cfg.OutboundProvider)` — static fallbacks first, then the shell provider for URLs it `OwnsURL`. `compositeProvider.Reset()` resets **both** halves (the shell when it implements `Reset()` — `subscription.Manager.Reset` clears every session's exclude list); a code-less exhaustion in `replaceOutboundServer` Resets before returning its `exhaustedError{allCodeLess}` (review 3 I-1/I-2: a static-only Reset left a k2subs session with every tunnel excluded → the first retry tick failed 503). **Origin**: `outboundTransport.fromShell` (set at `Start` by `shellOrigins`, and on every Phase-B swap by `providerShellOwns`) marks a URL the shell handed out; such a target answering `ErrNoCandidates` (a subscription refresh dropped / re-keyed its URL) is an **exhaustion** (capped → `OnOutboundFatal` → k2r rebuilds from a fresh subscription; desktop k2subs ends disconnected 503 after 10 min — the daemon does not rebuild), not manual mode (`Engine.noCandidates`, R1 review M-4). Manual mode and static-only targets keep retrying forever.
- **Pause (final-review-2 I1)**: while `e.paused`, retry-schedule ticks (`retrySet.deferDue`), net-event wakes and hold ticks do **no** netcheck and no race — a race would reinstall the connections Pause released; a race already in flight when Pause lands is not installed (`phaseA`). An echo re-race signal received while paused is dropped — no race, no escalate (sim PE). A Pause landing **mid-round** (sim PI) aborts it at the next check: `replaceOutboundServer` before each candidate setup and after a setup succeeds (the new TM is closed, no swap — `errPausedRound`), `retryPhaseB` / `escalate` before the `pre-exhaust` netcheck, `escalate` at entry (the echo-signal path), `retryOnce` at entry (a later target of the same tick), and after a hold / schedule tick's netcheck before its Phase A. Result `escPaused`: no cap accounting, no step change, nothing excluded that was not tried; a tick's target stays as scheduled, an escalating target joins the schedule (hold `retryingHoldError` 503); Wake's immediate tick resumes it. Residual: a Pause landing between that check and the swap a few instructions later is not seen. Paused time is excluded from the cap (`pausedAt`/`pausedTotal` on `holdNow`'s clock, `retrySet.counted`). `Wake()` pokes `holdWake` (trigger `wake`) after its status push, so the schedule / hold attempts at once.
- **Tick cadence and judgement (M3/M4/M8/M9)**: hold and schedule ticks judge **active-only** (`SkipPassive` for every trigger but `pre-phaseB`): behind an accept-all captive portal direct dials "succeed", and passive evidence would leave a 107 hold every tick for a candidate round. A target on the schedule `longPendingAfter` (10 min) ticks every `longPendingInterval` (60s). `hm.targetRecovered` for a **scheduled** target (`outboundTransport.scheduled`) or a **held** one (`outboundTransport.held`, set by `holdUntilOnline` while it blocks — device D2: the node carried traffic 2s after a 106 ended, the hold left ~29s later at its backoff tick) sends it on `recoveredWake`; the loop ticks it / the hold re-judges and runs its Phase A at once (trigger `recovered`), at most once per `holdBackoff[0]` since its last attempt, the backoff step kept — a tick, not an echo re-race signal (those stay dropped, review C). Muted (sim RW) while the target's latest Phase A was a code-less reject (`retryState.phaseACodeLess` / the hold's `codeLessA`: the echo only re-proves the node is alive — with Center hanging it fired every ~16s forever), and after a recovered tick that failed until the next backoff / net-event / wake tick has run (`recoveredMuted` / `muted`): at most one extra tick per cadence interval. A hold drops a recovered token for another outbound (its schedule ticks it after the hold). An iface-down (101) tick skips Phase A (hold and schedule alike) but still re-judges.
- **Netcheck DNS**: its own `DirectDNSClient` on `client.NetcheckDNS` when set (webapp overleap brand: overseas resolvers), else `client.DNS.Direct` (`netcheckDNSServers`; also in proxy mode), protected via `DialerController`. `netcheck_dns` is netcheck-only — `dns.direct` governs every direct-routed lookup and stays the engine default for both brands (final-review-2 M6). `directResolve` returns an A answer with addresses at once, alone (sequential dials in one 3s budget — IPv6-first would starve IPv4 on a v6-blackholed network, and waiting for a dropped AAAA query would spend the budget, M5); AAAA only when A is empty.
- **iOS display (spec §5.1 correction)**: iOS shows reconnecting only through `NEVPNStatus.reasserting`, set on an unsatisfied NWPath; the NE drops the engine's `reconnecting` push. So 106/107/503 holds and the whole 10-min exhaustion read **connected** on iOS until native reason passthrough (spec §6 item 5) lands. Android / desktop show reconnecting + reason.

## Error Classification (error.go)

HTTP-aligned error codes for frontend consumption (ranges are load-bearing: 1xx network, 4xx client, 5xx server — never mix):

| Code | Category | Meaning | Pattern |
|------|----------|---------|---------|
| 101 | network | Network unavailable | network unreachable, no route to host |
| 106 | network | No internet (interface up, nothing answers) | not pattern-matched — netcheck verdict `netNoInternet.holdError()` (`netcheck.go`). **Not** shown when no netcheck targets are configured (`netUnknown`, no gating) |
| 107 | network | Captive portal / interception | not pattern-matched — netcheck verdict `netCaptive.holdError()`: a target answered with the wrong status/body (redirects are not followed) |
| 108 | network | Timeout | net.Error.Timeout(), context.DeadlineExceeded |
| 400 | client | Bad config | parse URL, missing auth |
| 401 | client | Auth rejected | stream rejected |
| 402 | client | Payment required | by code, producer-typed: `wire.ErrMetadataRejected` wrapping `StreamError{Code:402}` (node metadata auth) and `config.FetchStatusError{Status:402}` (Center k2subs fetch; 400/401/403 map to same code, 5xx→503, else 570). Text fallback `payment required` only; bare word `subscription` deliberately NOT matched. A sticky 401/402 is not overwritten by outbound exhaustion, and a 401/402 re-race skips replacement candidates |
| 403 | client | Forbidden | pin mismatch, blocked CA |
| 412 | client | Environment setup failed (operator must fix the host) | any `provider.Start` failure (`providerStartError`, classified at the call site — sing-tun/wintun text is OS-localized); gateway `install intercept` / `iptables` / `ip6tables` messages |
| 502 | server | Protocol error | TLS/QUIC handshake failure |
| 503 | server | Server unreachable | TCP dial, connection refused; outbound replacement candidates exhausted on a healthy network (`outboundExhaustedError`, set by the producer); also the `reconnecting` hold reason when the outbound has no replacement candidates (no disconnect) |
| 504 | server | Rule bundles unavailable (retryable) | no bundle on disk after embedded seed, or a configured `match.region` bundle missing |
| 570 | server | Unclassified | fallback |

## Resource Ownership

> **谁创建，谁销毁。Borrower 只用不关。**

Engine creates provider, transports and tunnel in `Start()` and closes them in `Stop()`. Tunnel borrows provider and dialer references but **never closes them** — it only manages its own context, WaitGroup and connTracker. `tunnel.Close()` calling `provider.Close()`/`dialer.Close()` causes double-close panics (e.g. sing-tun `StopFD.Stop()` on macOS). Exception: an external provider (gateway) keeps its own pre-commit lifecycle — its creator destroys it.

`Stop()` order (everything closed OUTSIDE `e.mu` — `prov.Close()` can block on dnsOverride CGo, tunnel handlers call `ReportWireError()` which needs `e.mu`):

```
netCoord.close() → healthMonitor.stop() → reRaceCancel()   // goroutines that read tm/tunnel stop first
[extract + nil fields under e.mu, broadcast disconnected status]
networkMonitor.Close()   // fires callbacks
cancel()                 // engine context
prov.Close()             // stops new TUN packets + DNS override
closeOutboundTMs()       // drops wire connections; then each outbound's Close() (k2p closes ICE/QUIC)
tunnel.Close()           // cancel → conns.closeAll() → wg.Wait(); handlers fail fast because prov/tm are closed
ruleEngine.Close()
missReporter.Stop()      // last — may flush a final batch, blocks ≤5s
```

| Resource | Owner (create + destroy) | Borrower (use only) |
|----------|--------------------------|---------------------|
| provider | Engine (gateway: its own) | Tunnel, dnsHandler |
| transport/dialer (per-outbound TMs) | Engine | Tunnel |
| healthMonitor, networkMonitor | Engine | — |
| ctx + wg + connTracker, handler goroutines | Tunnel | — |

`connTracker.closeAll()` force-closes connections stuck in `pipe()`/`pipePacket()` so `wg.Wait()` returns promptly. A `Stop()` during `Start()` cleans up in the same order at step 9.

The first reconnect of a critical episode fires immediately ("the connection went stale" is worth one redial); if the redialed connection is critical again the path itself is lossy, and repeats wait `actionCooldownBase` (30s) doubling to `actionCooldownMax` (120s) — long enough for the channel selector's quality path (2 fresh backup samples at the 5s cadence + 10s sustain) to move traffic to tcpws in between. Ten consecutive healthy samples end the episode; a network reconnect (`doNetworkReconnect` → `resetActionBackoff` + `reconnect(false)`, i.e. the wiping `Reset`) forgets it. `resetCounters` (called by every reconnect) deliberately does NOT touch the backoff. Before this (ticket #3747, Android) a lossy-but-reachable QUIC produced a 10s reconnect loop that redialed the same path and wiped the selector's evidence each time, so the user could never reach tcpws. Pinned by `TestHealthMonitor_ReconnectBackoffGrowsAndResets` / `TestEngine_HealthReconnectPreservesScoreboard_NetworkReconnectWipes`. `sample()` uses primaryTM for heartbeat stats and for `HealthSnapshot`'s `ScoreQUIC`/`ScoreTCPWS`/`ActiveChannel` fields (`json:"score_quic"/"score_tcpws"/"active_channel"`, primary outbound only — same scope as everything else in the snapshot). It also calls `WireStats()` on every OTHER outbound in `hm.tms` (side-effect only, return discarded) — `WireStats()` is the one production path that primes a `ChannelScore`'s QUIC-quality component (`wire.TransportManager.RecordQUICStats`), so without this loop every non-primary outbound's `scoreQUIC.quality` would stay permanently uninitialized and its `ScoreQUIC` would be capped at `avail×0.5`, eventually false-tripping wire's quality-path switch-away on a perfectly healthy QUIC outbound. `echoLoop`: one primary-probe goroutine (`echoProbeLoop`) AND one backup-probe goroutine (`backupProbeLoop`), independently timed, per TM.
  - `echoProbeLoop` probes via `wire.EchoProber` on an exponential-trust schedule (`echoIntervals` 1s→16s, `echoProbeTimeout` 2s); 3 consecutive real failures trigger per-TM re-race, so wire death is detected in ~5s. **`reRaceFailStreak` decays on recovery** (review A): `healthMonitor.targetRecovered` (← `wireHealthRecovered`) resets it when the probe sees the node answer again — an echo OK, or a failure run ending without a Reset in between (an answered user dial) — so separate outages in one session never add up to Phase B. **Not-probed (`wire.ErrEchoNoConnection`) strikes only on user-dial evidence** (`echoStepDial` / `readDialFailEvidence`): dials are *failing* iff `tm.ConnectFailures()` has an unresolved failure (no later answered dial, no Reset/ResetConnections/ReplacePrimary) < `echoDialFailWindow` (30s) old AND the engine's network is up (`hm.netUp` ← `netCoordinator.isNetworkUp`, wired by `wireHealthNetUp`; mobile no-network → no strike, no new replace-loop work; desktop never reports down). While failing (S9 ruling 2026-11-05): for the first `echoDialFailFastFor` (**60s**) of the run the probe is pinned to `echoIntervals[echoDialFailTrust]` = **2s**, then back to the not-probed backoff (review C: manual mode on a dead node with a background app retrying is bounded; `TestDeadNodeTimeline_ManualModeDeadNodeBounded`); `DIAG: echo-probe-fail` for this class is Warn once per run, Debug after; a run's end zeroes dial-failure strikes (frozen quiet-tick strikes never leak into the echo path, review D — echo strikes from a cached connection are kept) and counts as recovery only on the not-probed path (review 3 M-1: over a cached connection an "answered" dial can be a UDP open that sent nothing); a Phase-B swap (new `ot.tm`) restarts the seq/gen/run bookkeeping and zeroes strikes (review E / 3 M-2); a tick preceded by a *fresh* failure (seq moved) is a strike, a quiet failing tick keeps the count (failures arrive in bursts); a re-race needs 3 strikes **and** the run (since `ConnectFailureInfo.First`) to have lasted `dialFailReraceAfter(k)` = 8s / 24s / +16s for the k-th re-race of that run (`echoLoopState.dfRunFirst/dfReraces`; a new run restarts k). That gate is what pins both bounds wherever the probe timer was: dead node → Phase B 29–31s after the first failing dial at ≥1 failure/2s (worst 37s at 1/3s; target 45s for `DIAG: outbound-failover`), and a 20s refusal never gets a second failed Phase-A (the first answered dial ends the run before 24s) → no Phase B — `echo_dialfail_timeline_test.go` drives both on a fake clock (`hm.clock` + `tm.SetConnFailClock`). Not failing → `echoStep`'s not-probed arithmetic unchanged (idle/offline cadence ramps to 16s as before). When the connection generation moved since the last probe a not-probed probe first zeroes strikes (gen is read **before** `RunEchoProbe`, so a Reset during a probe is seen at the next one), so old-path strikes never combine with a new-path failure. Caveat: a TCP-WS primary's not-probed probe re-connects, so the 2s cadence adds refused connects while (and only while) user dials are failing. One failure strikes at most once; idle = no dials = no strikes. This is what lets a node that refuses/402s every connection reach `outboundReplaceLoop` (and Plan A's 401/402 fail — the race error carries the code). A successful Phase-A (`phaseA`) also `ClearWireError()`s a stale non-user-action wire error (the connected+503 window after a hold). An `init()` guard panics if that worst case ever reaches QUIC `MaxIdleTimeout` — past that point the loop adds nothing over quic-go's own idle timer. **Backward compat**: `echoStep` routes `wire.IsEchoUnsupported` errors (pre-echo servers) to trust-growth rather than strikes, so old servers never storm re-races. That predicate is fail-open, and misreading a real timeout as "unsupported" is what silently disabled re-race entirely in ticket #3463 — see the timeout note in `wire/CLAUDE.md` before touching it. Each probe also feeds the dual-channel quality scoreboard: `RecordEchoResult(primaryChannel, ...)` + `EvaluateSelector(now)` (see `wire/CLAUDE.md` transport.go for the FSM this drives) — a second, uncoupled job on the same probe, never influencing trust/strikes.
    - **Strike gating (`suppressStrike`)**: scoring is never gated, but two topologies keep an echo failure OUT of the strike counter **while the TCP-WS channel has live proof of life**, because there a failing echo is expected rather than informative. (1) Fallback active (`ActiveChannel()=="tcpws"`) while the primary is still the QUIC dialer, AND `TCPWSChannelRecentlyHealthy(30s)`: that QUIC path is known dead — leaving it ungated, its timeouts strike 3× in seconds and fire a re-race that closes the QUIC dialer with no backup and `ReplacePrimary(tcpws)`es over the selector's whole fallback state, so the user never returns to QUIC; recovery of that path is owned by wire's `runProbeOnce`. (2) The primary IS the tcpws channel and `TCPRecentlyHealthy(30s)` is true: `TCPWSClient` became an `EchoProber` in this branch, so tcpws primaries now run the 1-16s schedule with a 2s timeout, and TCP head-of-line blocking under bulk transfer can blow that 2s three times in a row on a session that is working — the re-race would close the very session serving the transfer. With no recent TCP success, strikes accumulate normally in **both** topologies.
    - **Why case (1)'s proof condition is mandatory, and the trade it accepts**: `probeOnce` is the ONLY producer on `reRaceChan`, Phase B server replacement (`replaceOutboundServer`) is reachable only through it, and `assess()` cannot reach critical on TCP-WS stats — so there is no other automated escalation. Suppressing on topology alone would sever it exactly when the NODE dies while a user sits in fallback (crash, quota cutoff — routine fleet events), leaving both channels dead and the user hung until a network change or manual reconnect. Accepted trade: an **idle** fallback user produces no dials, so has no live proof, so strikes resume and a re-race may land tcpws as primary — which is now a stable, honest terminal state (the C1 topology gates stop the FSM and the recovery probe from fabricating a QUIC channel there). The idle case is thus the pre-fix status quo minus the phantom loop. Note the proof clock is fed by **`DialTCP` only** (wire's `recordTCPWSDialSuccess`): that path reads a server response, so success is end-to-end; UDP dials over tcpws open a smux stream with no round trip and keep "succeeding" against a dead node, which would manufacture exactly the proof this gate must not have.
    - **Honest scope of root cause C**: the spec claimed channel switching would leave re-race entirely. What is delivered is narrower — re-race no longer fires *from the dead primary during fallback* or *from a loaded-but-working tcpws primary*; it remains the escalation for every other echo-death, which is its intended "this outbound is beyond channel choice" role.
  - `backupProbeLoop` opportunistically echo-probes the currently-inactive channel on its own timer (never piggy-backed on `echoProbeLoop`'s tick, which would distort its re-race timing invariant). Scope is asymmetric: active=="quic" → probes tcpws at `backupProbeIntervalHealthy` (60s), upgraded to `backupProbeIntervalDegraded` (5s) once `ScoreQUIC` drops below `echoBackupProbeThreshold` (0.7, mirrors wire's private `qualityDegradeThreshold`) so the quality path's `backupFresh` gate has fresh samples by the time it needs them; active=="tcpws" → no-op, because QUIC recovery probing during fallback is already owned by wire's `runProbeOnce` (see `wire/CLAUDE.md`). `hm.mobilePowerSaving` (desktop `false`, set from `Config.MobilePowerSaving`) narrows this to **distressed only** (`primaryDistressed`: the health FSM in `critical`, which only smoothed loss > 0.25 can reach, **or** `wire.TransportManager.DataPathDistressed` — three consecutive quic `DialTCP`s sent and never answered): while QUIC is healthy or merely degraded *and answering requests*, mobile probes nothing and relies on protocol keepalive; once distressed it probes at the 5s cadence until the selector switches or QUIC recovers. The second key (round 3, #3757) closes the loss gate's blind band: CC loss only moves when a monitor interval completes, so an app-limited sender reports `loss=0.000` for minutes while every request dies at the 5s deadline, and the loss-only gate never opened (#3757: 205/260 QUIC heartbeats at loss 0; the emulated per-flow-policed link took 32s of dead dials to cross 0.25). Desktop is not gated but its cadence upgrade was score-only; distress now upgrades it to 5s as well, since the selector's data-path fast path needs two fresh tcpws samples and the 60s cadence would take a minute to supply them. Health grading itself is untouched — distress opens probing, `wire`'s selector decides. Pinned by `TestBackupProbe_MobilePowerSavingProbesWhenDataPathDistressed` / `TestBackupProbe_DesktopCadenceUpgradesOnDataPathDistress`. **The gate's early returns are a WAKE cadence, not a probe cadence**: all three (`mobilePowerSaving && !critical`, `active != quic`, tcpws-primary) return `backupProbeIntervalDegraded` (5s) — pure in-memory checks, no radio — because that return value is `backupProbeLoop`'s only wake source; the original #3747 fix returned the 60s healthy interval there, so the gate opening (and a rollback to quic) was noticed up to 60s late, and since the first critical's reconnect closes the gate again for ~7s via `resetCounters`, a wake landing in that gap slept another 60s. The backup echo runs under its own `backupEchoProbeTimeout` (5s, not the primary's 2s `echoProbeTimeout`): the backup tcpws is usually cold (every health-critical `ResetConnections` drops its session too) and a cold TCP+TLS+WS+smux+metadata dial from cellular does not fit in 2s — a spurious timeout here is not a strike but a false availability sample that drags `scoreTCPWS` under `minSwitchTargetScore` exactly when the switch needs it. It is keyed on the health grade, **not** on `ScoreQUIC < 0.7`, on purpose: the score carries an RTT term, and cellular bufferbloat under a healthy download drives it to ~0.5 while a tcpws first measured under that same load gets a loaded min-RTT baseline (ratio ≈ 1.0) — score-gating would switch a healthy download onto tcpws. Loss separates "the UDP path drops bulk" (ticket #3747: carrier UDP QoS, handshake and echoes pass, nothing loads, tcpws — which the DNS control plane was already using — never got a sample) from "the shared queue is full". Pinned by `TestBackupProbe_MobilePowerSavingProbesWhenLossCritical`.
  - TCP health gate: `TCPRecentlyHealthy()` (30s window) suppresses reconnect when TCP streams are working — and, as of the final review, the echo strike above. It answers for whichever primary is installed: `*QUICClient`'s own `lastTCPSuccessAt`, or (tcpws-as-primary) the TCP-success clock `wire.TransportManager` records on `DialTCP`'s tcpws success paths. It returned a flat `false` for every tcpws primary before that second branch existed, which would have made the strike gate a silent no-op in exactly the topology it targets. Wire-layer metrics only — relay metrics are observability (see `wire/VOCABULARY.md`). `wakeDetector` (embedded in healthMonitor): detects sleep/wake via wall-clock gap, `DIAG: wake` at >5s, triggers `doWakeReconnect()` at ≥30s (aligned with QUIC MaxIdleTimeout) — the **scoreboard-preserving** reconnect (`reconnect(true)` → `ResetConnections`, backoff kept), because a wake says the connections are stale, not that the path changed; a path change arrives separately as a NetEvent / sing-tun interface change and goes through `doNetworkReconnect()` (`Reset`, backoff forgotten). `Pause()`/`Wake()` preserve the scoreboard the same way (iOS calls them on every screen lock/unlock). Before this every phone pickup on a lossy-but-reachable QUIC put the user back on it and replayed the whole escape. Pinned by `TestEngine_PauseWakeAndWakeReconnectPreserveScoreboard`. Heartbeat includes memory metrics (`heapMB`, `sysMB`, `goroutines`) via `runtime.ReadMemStats` every 30s for iOS NE jetsam diagnosis, plus `activeChannel`/`scoreQuic`/`scoreTcpws` (Task 8) so the dual-channel scoreboard is visible without DEBUG — see the heartbeat field list in `k2/docs/diag-events.md`.
