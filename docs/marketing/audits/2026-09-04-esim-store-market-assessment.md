# eSIM 商店：市场评估与执行决策（2026-09-04）

- 类型：时间点快照（决策备忘）
- 结论：**封存**。旅行流量 eSIM 是红海不做；海外号码 eSIM 需求真实但按当前规模收入不成立，用近零成本动作验证需求与设备面，满足三条重启条件再按已写好的 spec 开发。

## 1. 这是两个生意，不是一个

| | 旅行流量 eSIM | 海外号码 eSIM |
|---|---|---|
| 用户任务 | 出境上网 | 注册 Google / ChatGPT / Telegram / X 等海外服务时收验证码 |
| 市场形态 | **红海**：Airalo、Holafly、亿点连接、环球漫游、联通移动跨境卡、飞猪携程 | **散市场**：淘宝 Ultra PayGo 实体卡、giffgaff 邮寄、香港万能卡、灰色接码平台，没有品牌化产品，体验差 |
| 客单价 | $10 到 $20 一次性 | 订阅制，消费级锚点 $36/年（Ultra PayGo），giffgaff 近乎免费 |
| 竞争方式 | 拼价格与投放，独立获客成本 $5 到 $15 | 拼便利与信任：eSIM 即装、不用淘宝、app 内管理、绑定既有账号 |
| 与开途的关系 | 配菜 | 同一条任务链的下一步（翻墙 → 注册海外服务 → 需要海外号码） |
| 判断 | 不做 | 有机会，但要看规模 |

## 2. 独立 app 还是并入开途

**当时的结论：先并入开途做「扩展」，但从第一天起当成可拆出去的独立产品线来建，等指标说话再拆。**

### 2.1 为什么先并入

- 获客成本几乎为零，而这是 eSIM 生意最大的成本。开途已有付费用户、账号、支付、钱包、工单、分销体系。
- 使用场景是同一条链，不是硬凑的交叉销售。
- 号码是订阅制，绑在账号上，提高留存和切换成本。
- 验证成本最低：并入等于内部测试与 alpha 阶段；独立 app 是先付全部成本再验证。

### 2.2 并入的三个真实风险与压法

| 风险 | 压法 |
|---|---|
| 中国区 App Store 上架资格是开途最稀缺的资产，VPN app 加 eSIM 安装与新隐私数据类型会引来审核关注 | app 内只做管理与安装、不卖不结账（spec v2 已落实）；整个功能挂远程配置开关，可一键隐藏；原生安装 SDK 单独版本发布 |
| 「接码」在中文互联网与黑灰产绑定，反电诈法盯手机卡买卖 | 对外文案一律「出境旅行与海外生活的号码和流量」，永不出现「接码」「验证码专用」；每账号限 2 到 3 个号码；条款禁止批量注册与转售 |
| 品牌稀释 | 网站上给这条线一个子名字和独立页面，app 里只是一张发现页卡片，随时可整体搬走 |

### 2.3 什么时候该拆成独立 app

| 指标 | 信号 |
|---|---|
| 附着率（活跃付费用户里买过 eSIM 的比例） | 低于 3% 是配菜，高于 8% 能独立站住 |
| 非 VPN 买家占比（网站 eSIM 页搜索带来、只买 eSIM 不买 VPN 的新注册） | 这部分人是独立产品的市场 |
| 审核与合规摩擦 | 任何一次因 eSIM 卡审或供应商投诉，都是拆出去隔离风险的理由 |

技术上拆得动：仓库品牌参数化，网站与 API 共用，第三个品牌就是一个新的 app 构建；真正的成本在市场端。

### 2.4 顺带的观察：Overleap 那一侧逻辑可能反过来

海外用户来中国旅行最痛的是到了就断网，一张香港出口的「来华 eSIM」不装软件就能上网，门槛比装 VPN 低得多。那条线更像独立产品或获客入口，等 Overleap 用户画像数据回来再议。

## 3. 值不值得现在做：按真实规模算账

| 数字（2026-09-04） | 值 |
|---|---|
| 总用户 | 5,471 |
| 累计付费用户 | 864 |
| 活跃付费用户 | 503 |
| 近 30 天新注册 | 839 |
| 移动设备 iOS / Android | 3,372 / 313（iOS 约 92%） |
| 机型与系统版本遥测 | 全部 unknown（未采集） |
| 号码线年化收入，按 10% 附着率、$40/年 | 约 $2,000（活跃）到 $3,500（累计） |

- 这点收入对应后端、网站、webapp、原生 SDK 四条线数周工程量，**纯收入上不成立**。
- **设备面**：用户几乎全是 iPhone，国行 iPhone 除 17e 与 Air 外没有 eSIM，能装的只剩港版外版机，可触达可能只有一两成；且目前连这个比例都查不出来。SIM 转 eSIM 适配卡能缓解，但引入实体物流，削弱「即买即装」的卖点。
- **监管观感**：海外号码在中文语境的敏感度高于流量卡。
- **供应商未验证**：号码段能否被 Google / Telegram / WhatsApp 判为手机号、大陆漫游能否收码，都没有供应商承诺。

---

## 4. 决策

**封存**。spec 与调研保留，不写实施计划，不做供应商 pilot。

**重启条件（三条同时满足）**：

1. 付费用户 ≥ 3,000；
2. 预约页对存量付费用户的预约率 ≥ 10%；
3. 活跃设备中 eSIM 可用比例 ≥ 30%。

## 5. 现在就做的近零成本动作

| 动作 | 成本 | 回答的问题 |
|---|---|---|
| app 上报机型、系统版本、eSIM 能力（Android `hasSystemFeature(FEATURE_TELEPHONY_EUICC)` + `EuiccManager.isEnabled`；iOS 按机型标识与地区推断） | 1 到 2 天，本来就该补的遥测 | 重启条件 3；所有硬件相关决策都用得上 |
| 网站「海外号码 eSIM，$39/年」预约页 + 给存量付费用户一封邮件 | 半天 | 重启条件 2；launch 框架里的 waitlist 阶段 |
| 发现页放联盟链接（Airalo、giffgaff 等有 affiliate 计划） | 零开发、零合规暴露 | 现在就满足用户场景，当渠道不当供应商 |
| 供应商 pilot（Telnyx 自助 + esim.tech 询价 + 两张对照卡，约 $50） | 延后 | 只回答「能不能做」，不回答「值不值得」；预约率出来后再花 |

## 6. 保留下来的资产

- 设计 spec v2：网站只卖（NextPay 订阅）、app 只用（K2Plugin 原生安装 SDK）、eSIM Access 流量适配器、`esimprovider` 接口、数据模型、worker、webhook 幂等、错误码与契约门。重启时可直接进 writing-plans。
- NextPay 结论：托管结账页返回 `PaymentURL`；订阅是 NextPay 自管循环账单，卡自动续费，支付宝/微信由 NextPay 发 14/7/3/1 天提醒手动续费，到期即 expired 无宽限；webhook HMAC 且至少一次投递需按 `evt.ID` 去重；SDK 每进程单 App（Overleap 接入前需改 qtoolkit）；无 App 侧退款 API；只收 USD。
- 平台事实：iOS 安装只能走 17.4+ 通用链接；Android 非运营商 app 可原生安装；国行设备限制；Apple 3.1.3(e) 禁止 IAP 卖 eSIM。
- 供应商与国家结论：见调研沉淀文档。
