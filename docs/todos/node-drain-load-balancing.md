# 节点排空 / 负载均衡调节（服务端指令迁移客户端到其他节点）

## 优先级: P2（未排期）

## 定位（2026-10-30 David 决定）

做成**节点负载均衡调节**能力，**不作为镜像升级优化**。升级中断另走「优雅退出 + 关闭帧带 restarting 原因码」（约 3 天，单独做）。

## 是什么

节点向在线客户端下发「请迁移」指令，客户端**先连新节点再断旧节点**（make-before-break）：新连接走新节点，已有连接留在旧节点自然结束，排空窗口到期后旧节点再处理。用户基本无感。

用途：
- 节点过载时把一部分用户调到同地区空闲节点；
- 流量额度临近时先排空，取代 sidecar 现在直接 `docker pause` 的硬切；
- 节点迁移/下线（如 Lightsail→Vultr）、IP 被封后转移用户。

## 设计要点（评估结论）

- **不下发完整 URL**：指令只说「请迁移 + 建议节点 id」，客户端只在**自己已有的节点列表**里选。节点能下发任意地址+pin = 被劫持节点可把用户导向假服务器。
- 保持用户所选地区；无同地区节点、专属线路 → 退化为原地快速重连。
- 出口 IP 会变：Netflix/银行/ChatGPT 等按 IP 绑会话的站可能要求重新验证。
- 迁移要分批错开，避免把一个节点的用户一次性压到邻居上。
- 老客户端忽略新指令，退回现有行为。
