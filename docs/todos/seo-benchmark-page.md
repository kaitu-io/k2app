# 公开对比测评：k2 在不同丢包 / 延迟下的实测（方法 + 数据 + 文章）

**优先级：P1** · 立项 2026-11-10（David）· 取代本文件 2026-02 的旧版计划，并吸收已删除的 `k2-vs-{shadowsocks,vless-reality,wireguard}-comparison.md` 与 `seo-competitor-interception.md`（其中 Cloudflare Tunnel / Ngrok / FRP 内网穿透拦截不是开途受众，不做；需要可从 git 历史恢复）

## 为什么要做

站上现在能引用的只有 `k2/docker/bench/results/REPORT.md`（2026-02），它撑不起公开发表：
- 丢包只加在客户端出方向（ACK），下载数据本身不丢 —— 不是"26% 丢包下的下载速度"
- macOS Docker Desktop、每场景 1 轮、无置信区间，测的是旧 K2ARC 而非现网 k2cc
- 没测 Cubic，却在文案里写过"Cubic 不足 10%"（已于 2026-11-10 删除）

目标：一份**任何人都能复现**的测评，让搜索引擎和 AI 引用时有可信出处；结果输的场景也照实写。

## 一、测试方法（先定方法，再跑数）

**拓扑**：PVE 测试机房三台 Linux VM —— client ↔ router ↔ server。损伤只加在 router 的**两个方向**（netem + ifb），client/server 不动；不用 Docker Desktop。

**参测对象**（2026-11-10 按 Bing 中国区 90 天搜索量重新评估；版本全部锁定写进报告）：

| 参测 | 覆盖的搜索词（曝光） | 为什么测 |
|---|---|---|
| VMess + WS + TLS | v2ray 76,095 · vmess 2,585 | 量最大，经典配置 |
| VLESS + Reality（Xray） | xray 8,241 · vless 4,800 · reality 4,385 · vless reality 1,340 | 当前 TCP 主流 |
| WireGuard | wireguard 32,003 | 量大；无伪装，真实链路大概率被识别——存活率本身就是结论 |
| OpenVPN | openvpn 25,663 | 量大；同上 |
| Shadowsocks（2022） | shadowsocks 14,644 | 量大；全加密流量正是 USENIX'23 研究的对象 |
| Trojan | trojan 6,402 | TLS 类代表 |
| Hysteria2（Brutal / BBR 两模式） | hysteria2 2,994 · hysteria 2,589 · hy2 952 | QUIC 类直接竞品 |
| AnyTLS | anytls 2,172 | 新协议，量在涨 |
| TUIC v5 | tuic 309 | 量小，但它是 QUIC 同类，技术对比需要 |
| 基线：直连 TCP Cubic / BBR | — | 让读者知道"什么都不用"是什么水平 |

不测：NaiveProxy（318）、Snell/Juicity 等量极小的。「协议对比」「翻墙协议」「v2ray 速度」这类对比长尾词 Bing 量均为 0 —— **流量在协议名本身**，所以每个协议要有自己的落地页（见第二节）。

**场景矩阵**：
- 随机丢包 0 / 1 / 2 / 5 / 10 / 15 / 20 / 26 / 30 / 40 / 50 %
- RTT 50 / 150 / 250 ms（对应香港 / 日本·新加坡 / 美西）
- 瓶颈带宽 100 Mbps
- 突发丢包（Gilbert-Elliott），模拟运营商晚高峰
- UDP 限速 / 按流 QoS（复用 `k2/test` nslab 的知识：大包丢弃、按流限速）—— 这是 QUIC 协议的真实弱点，必须测，输了也写
- 每个点 ≥5 轮，报中位数 + 四分位距

**UDP → TCP 切换时机（单独一组）**：只有 k2 会在 UDP 不通时自动切到 TCP-WS，这是 QUIC 类协议（Hysteria2 / TUIC）没有的能力，要量化：
- 突然断 UDP：传输中途在 router 上丢弃全部 UDP:443 → 测「零吞吐持续几秒」「切换后吞吐」
- UDP 被限速 / 大包丢弃（运营商 QoS 的真实形态，nslab `BIG` / `HASHLIMIT_RATE` 同款）→ 测多久判定、是否误切
- UDP 逐步恶化（丢包 0→60% 爬升）→ 测在哪个丢包点切换、切换前后速度
- UDP 恢复 → 测多久切回 QUIC
- 对照：Hysteria2 / TUIC 同场景（预期断流不恢复），VLESS-Reality（纯 TCP，不受影响）
- 输出：一张「时间轴吞吐图」，标出断 UDP 时刻和切换时刻

**指标**（技术口径，页面上再翻译成用户语言，见下）：60 秒下载吞吐、负载下延迟、网页加载时间（小文件 / 多请求，更接近真实使用）、建连成功率、吞吐稳定性（CV）

**真实链路层（第二层证据）**：testlab 有大陆出口 → 东京节点，分时段（白天 / 晚高峰）连测 N 天。再加上车队 cc-summary 的聚合统计（丢包分布 × 用户评分，匿名），说明实验室场景和真实网络的对应关系。

**公信力要求**：
- 脚本、配置、原始 CSV 全部公开（仓库 + 页面可下载）
- 写明利益相关：测评由开途自己做
- 每个场景给出复现命令
- 结果里 k2 输的场景照写、并解释原因

## 二、给普通用户看的表达（页面首屏必须做到）

技术读者看表格，普通读者只看图和一句话。页面首屏放这几样，不放 Mbps 原始数：
1. **一句话结论**：「丢包 20% 时，k2 保住了 X% 的速度；Hysteria2 Y%、VLESS-Reality Z%、WireGuard W%。」
2. **主图：速度保持率曲线** —— 横轴丢包率 0–50%，纵轴「还剩多少速度（相对无丢包）」，每个协议一条线；背景色带标出「日常 1–2%」「晚高峰 5–15%」「敏感时期 20%+」，读者一眼看出自己处在哪一段。
3. **换成生活单位**：吞吐折算成「能不能流畅看 4K（≥25 Mbps）/ 1080p（≥5 Mbps）」的✔/✘矩阵；网页打开时间用「秒」画条形图。
4. **UDP 被封那一刻**：时间轴图 —— 「k2 断流 N 秒后自动恢复；Hysteria2 一直断着」。
5. **每个协议一张小卡**：适合谁、在哪种网络下吃亏（含 k2 自己吃亏的场景）。
6. 图全部用 SVG（文字可被索引），alt 写出关键数字；同一数据在下方给表格版。

### 域名与措辞隔离（David 2026-11-10 提出：怕敏感对比内容连累微信分享 / 主站被封）

原则：**新用户在没有工具时必须能打开的东西（下载页、安装包、分享链接）**和**会招来审查注意的东西（协议对比、GFW 分析）**不放在同一个域名上。封锁和微信拦截都按域名生效，不按路径——放在 kaitu.io 的子路径下起不到隔离作用。

1. **测评和协议对比放 GitHub Pages，不买新域名**（David 2026-11-10 定）：以 k2 开源项目身份建一个中立的 GitHub 组织 + 仓库（名字不带 kaitu/开途；旧的 `kaitu-io/k2` 仓库已退役，不复用），测评脚本、原始 CSV、结果页都在里面，`*.github.io` 发布。封 github.io 的代价对审查方很高，比自建小域名稳。正文不做开途营销，只在「谁在用 k2」处单向链到 kaitu.io。首发渠道 **V2EX**，之后 Telegram 技术频道 / X。现有 `/k2/*` 技术文档是否迁移，另议。
2. **kaitu.io 保持「干净的产品站」**：标题和 meta 不出现 翻墙 / 梯子 / GFW / 防火长城 / 审查 / 封锁；用「跨境网络」「运营商限速」「丢包」这类中性技术词。用户指南照写，只换措辞。（现状：全站 UI 文案干净，「安全审查」指安全审计；敏感词集中在 /k2 文档和两篇指南）
3. **微信 / QQ 里分享用专门的落地域名**：页面只有产品介绍 + 下载按钮，不链协议站；被拦截就换域名，不牵连主站和 SEO 站。
4. 现状（David 2026-11-10）：大陆目前没有封锁开途，暂不需要可达性监测。
5. 这些措施只能降低风险，不能保证不被拦截——微信的判定规则不公开。

## 发布门槛（David 2026-11-10：效果真的好了才发）

**跑数前先把门槛写死**（避免事后挑数据）。达不到就不发，先把结果交给 k2cc / 传输层迭代，修好后整套重跑：
- 丢包 10–30% 区间：k2 的速度保持率在所有参测协议里排前二
- 突然断 UDP：k2 恢复到可用（≥1080p 码率）的中位时间 ≤ 10 秒，且 Hysteria2 / TUIC 同场景未恢复
- 真实大陆链路（晚高峰）：k2 连接成功率 ≥ 99%、中位速度不低于 VLESS-Reality
- 0–2% 低丢包：k2 不比最好的协议慢 20% 以上（这里输得太多会被一眼看穿）

即使达标发布，也必须展示**全矩阵**，包括 k2 输的格子——只挑赢的场景发，会被 V2EX 读者当场拆穿，反噬比不发更大。

## 风险

- 实测可能显示 k2 在部分场景不占优 —— 照实发；这比无源数字更有说服力
- UDP 被限速的场景下 QUIC 吃亏，k2 会自动切 TCP-WS：要单独测切换后的表现
- WireGuard / OpenVPN / Shadowsocks 在真实大陆链路可能直接连不上：实验室层照测性能，真实链路层报「存活率」，两层分开写，不混为一谈
- 竞品配置要用官方推荐配置，否则会被质疑故意调差
