# GFW 工作边界

**日期**：2026-07-28
**用途**：为 [`spec.md`](spec.md) §2 提供依据。协议设计的取舍建立在本文档上，而非建立在"审查者能做什么"的想象上。

---

## 0. 为什么要有这份文档

`spec.md` 最初的威胁模型（T1–T6）列的是**审查者能做什么**。那是一份能力上限清单，用它做设计会得出"什么都要防"的结论，而"什么都要防"等于没有优先级。

设计需要的是**审查者会做什么**——已部署、常态执行、成本可承受的那一部分。本文档界定的就是这条线。

**这份文档会过期。** §1.2 的 ECH 假设过期了约两年而无人察觉，本文档承担同类风险。§6 给出失效判据，§7 给出复核周期。

## 0.1 证据分级

每条结论必须标注三件事：**结论 / 证据等级 / 观测年份**。

| 等级 | 含义 |
|---|---|
| **高** | 同行评审论文，有原始测量数据与可复现 artifact |
| **中** | 有原始数据的技术报告，或多个独立可复现观察 |
| **低** | 社区经验陈述，无原始数据 |
| **无** | 未检索到公开证据 |

**「无公开证据表明在做」≠「已证明不做」。** 两者结论不同，全文不得混用措辞。特别地，某些行为（如审查方购买商业服务枚举节点）从外部**本就极难测量**，此处的证据缺失说服力很弱。

## 1. 确认在用 · 全量常态 · 线速

| # | 能力 | 事实 | 等级 | 年份 |
|---|---|---|---|---|
| 1.1 | **全加密流量检测** | 不识别"加密流量"，而是用**豁免规则**放行像已知协议的流量、封锁其余。规则至少五组：已知协议指纹、置位比特比例（粗糙熵检验）、可打印 ASCII 的数量 / 比例 / 位置 | 高 | 2021-11 起，2023 发表 |
| 1.2 | **误伤容忍度 ≈ 0.6%** | 为确保无循环工具漏网，接受约 0.6% 的合法加密流量被误封 | 高 | 2023 |
| 1.3 | **TCP SNI 黑名单** | 明文 SNI 匹配 → 伪造 TCP RST 注入 | 很高 | 长期 |
| 1.4 | **QUIC SNI 黑名单** | **规模化解密 QUIC Initial 包**提取 SNI。有状态：按 UDP 四元组跟踪，60s 超时。命中后**丢包**（非 RST），对「同源 IP + 目的 IP + 目的端口」残留封锁 **180s**。黑名单约 **5.8 万 FQDN，与 TCP 黑名单相互独立** | 高 | **2024-04-07 起**，2025 发表 |
| 1.5 | **省级防火墙** | 河南自 2023-08 起独立部署，基于 TLS SNI + HTTP Host，**只审查出省流量**。累计封锁 **420 万域名 ≈ GFW 的 5 倍**（峰值时刻达 10 倍），策略更激进、更多变、对网络扰动更不鲁棒。河北、西藏、新疆已运行 **4 年以上** | 高 | 2023-11 – 2025-03 测量 |
| 1.6 | **目的 IP 黑洞** | 对已确认的循环节点直接封锁 IP | 很高 | 长期 |

**1.1 的直接推论：发真 TLS ClientHello 的流量命中协议指纹豁免，不进入全加密流量封锁路径。** 这是 TLS 伪装类协议（含本协议）最大的一项免费红利，也是它们仍然可用的根本原因。

**1.4 的直接推论：QUIC 上的伪装不比 TCP 便宜。** GFW 已经在解 Initial 包，且 Initial 的 Token 字段本就是明文——**连解密都不需要**。

## 2. 确认在用 · 触发式（非普查）

| # | 能力 | 事实 | 等级 | 年份 |
|---|---|---|---|---|
| 2.1 | **主动探测** | 被动启发式命中后才对目标发起探测，**不是普查**。Shadowsocks 场景下 **13 条真实客户端连接即足以触发**。探测来自大规模 IP 池 | 高 | 2020 |

**条件化的读法**：主动探测的频率**取决于我们是否先通过了 §1.1 的豁免**。通过了，很少被探；没通过，十几条连接就会招来探测，且很快。

因此 `spec.md` 的 P2（探测无法证实）仍然承重，但它防的是**低频事件**，不是常态。

## 3. 无部署证据

| # | 项 | 状态 | 说明 |
|---|---|---|---|
| 3.1 | 对已建立的 TLS 流做长时程包长 / 时序序列分类并据此封禁 | **无证据** | 见下方成本论证 |
| 3.2 | 按目的 IP 做**聚合**人群画像（"这个 IP 背后全是长肥连接，不像它声称的那个站"） | **无证据** | 同上 |
| 3.3 | **SNI 与目的 IP 归属不匹配即封** | **无证据** | 旁证：2019 年测量结论为 GFW 的 SNI 过滤"几乎从不是唯一封锁手段"，通常与 DNS 投毒、IP 封锁**对同一个黑名单域名**叠加使用——即针对**黑名单**，而非针对**不匹配** |

### 3.4 成本论证，以及它的边界

一个诱人但**错误**的论证是"旁路架构结构上做不到长时程分析"。§1.4 推翻了它：GFW 愿意为封锁**规模化解密每条 QUIC 流的 Initial 包，并维持 60 秒的四元组状态**。这比"每流状态太贵所以不做"要激进得多。

正确的论证是**成本量级**：

- 解一个 Initial 包 = 一次密钥派生 + 一次 AEAD，**一次性、可在首包完成、无需保留历史**
- 跟踪一条小时级连接的形状 = 持续保留时序与长度序列、跨小时维持状态

两者相差数个数量级。而且 §1.4 的论文观测到 **QUIC 封锁效果存在昼夜波动、与流量负载相关**——说明 GFW 在现有工作量下**已经处在算力边缘**。

**所以 3.1 / 3.2 的降级依据是「无部署证据 + 成本高出现役能力数个数量级 + 现役能力已显出算力压力」，不是「结构上不可能」。** 这个措辞差别决定了我们要不要继续观察——要。

### 3.5 关于 3.3 的赌注，以及它的参照数

`spec.md` §5 的 L4（SNI 与目的 IP 不匹配）没有消除手段，整个设计押在"审查者不会仅凭此封禁"上。

**§1.2 的 0.6% 是目前唯一可用来校准这个赌注的实测数字。**

按"SNI 与 IP 归属不匹配即封"会误伤的范围：CDN 回源、企业 TLS 前置代理、云负载均衡、anycast、一切用第三方域名的托管服务。**这个量级远超 0.6%。**

赌注因此从"未经检验的直觉"变为"有参照数、有反证方向的判断"。**它仍然是赌注**，但它现在可以被证伪：若观察到 GFW 接受远高于 0.6% 的误伤，本判断作废。

## 4. 未检索到公开证据，且从外部难以测量

| # | 项 | 状态 |
|---|---|---|
| 4.1 | **审查方购买商业 VPN 账号、注册后枚举节点 IP** | **未检索到任何学术测量** |

**此处的证据缺失说服力很弱。** 这类行为不产生可从网络外部观测的信号，缺乏公开研究是预期之中的，不构成"不发生"的证据。

**唯一可得的数据在我们自己的运营日志里**，且判据很清晰：

- 新节点在**向用户下发之前**即被封 → 扫描 / 探测发现
- 新节点在**下发之后**才被封 → 买号枚举

这两者的应对方向完全相反（前者投协议层，后者投节点生命周期与按用户分区），因此这项复核**优先级高于任何协议层改进**。

## 5. 钝器能力：2025-08-20 事件

北京时间 00:34–01:48（**74 分钟**），GFW 对 **TCP/443 无条件注入伪造 RST+ACK**，完全不检查内容与 SNI；端口 22 / 80 / 8443 / 1–72 不受影响；双向触发；每次三个 RST+ACK，TTL 与窗口值递增（与已知 GFW 设备指纹不同，疑为新设备上线或配置错误）。

**读法必须克制。** 它没有"证伪 443 伪装"——恰恰相反：**它误伤了中国全部 HTTPS，所以只持续了 74 分钟。** 它证明的是钝器能力存在、且其代价大到无法常态化，与 §1.2 的 0.6% 是同一个故事的两面。

对设计的唯一实际含义：**不要把可用性完全押在单一端口上，需要非 443 的回落路径。**

## 6. 边界失效判据

本文档若过期，我们**从自己的数据里**能看到什么。每条都是可监测的具体现象，不是原则性表述。

| 观测到 | 含义 | 应做 |
|---|---|---|
| 节点被封，但入站日志**无异常探测痕迹** | 存在我们不知道的**被动**判据；§3 的降级动摇 | 立即复核 §3，暂停按本边界做的降级 |
| **只有长会话用户所在的节点**被封 | 流量形状（§3.1）真的被用了 | §14 从"接受暴露"回升为必须处理 |
| 新节点**在下发给用户之前**即被封 | 扫描发现，协议层有破绽 | 查首包指纹（TCP 与 QUIC 分别查） |
| 新节点**在下发之后**才被封 | 买号枚举（§4.1） | **停止追加协议层投入**，转投节点生命周期与按用户分区 |
| 首包即被 RST，且外层 SNI 不在已知黑名单 | §1.1 豁免失守，或指纹被单独识别 | 复核 uTLS 与真实浏览器的差异 |
| 同一 front 在部分省份可用、部分不可用 | 省级黑名单（§1.5）命中 | front 清单需分省维护 |
| 观察到 GFW 接受远高于 0.6% 的误伤 | §3.5 的赌注作废 | L4 从"赌注"改为"已失效"，全设计需重估 |

## 6.1 一次失败的尝试：从墙外测不到 SNI 封锁

**2026-07-28。** 试图绕开"需要境内观测点"这个约束：从墙外**往境内**发 TLS 握手（目标为 CERNET 的 443 端口），SNI 填候选域名，指望包穿过 GFW 时命中黑名单被 RST。

**方法不成立。**

| SNI | 结果 |
|---|---|
| `www.facebook.com` | ok / ok / ok（3 个干净目标） |
| `twitter.com` | ok / ok / ok（3 个干净目标） |

两个都是板上钉钉被封的域名，6 次读数零 RST。**GFW 的 TLS SNI 过滤在"外→内"方向不触发**，因此从墙外得到的任何"未被封"读数都无意义。

**同一次实验还产出了一个教科书级的假阳性，值得单独记住**：首轮 6 次 RST 中有 **5 次全落在同一个目标主机上、横跨 5 个不同 SNI**，且起始于该主机刚收到一个被封 SNI 之后。这是**残留封锁**——命中后 GFW 会封锁 `(源IP, 目的IP, 目的端口)` 数分钟——它会让一个被污染的目标读起来像"什么都被封"。当时的轮转周期（7 个目标）远短于残留窗口，等于没防住。更糟的是 go/no-go 门把这个假阳性**当成了方法有效的证据**放行了。

**两条教训已写进工具**（[`tools/sni_gate_probe.py`](tools/sni_gate_probe.py)）：

1. 每次 RST 后**立刻用无害 SNI 复测同一目标**；若也 RST，则该目标已污染，读数作废；
2. 阳性对照必须**全部**命中才放行，"命中一次"不算——那正是当时误判的来源。

**结论**：`spec.md` §10 第 1 项的硬门槛**确实需要境内观测点**，这一点现已从判断升级为实测事实。工具已按正确方向（境内 → 境外目标）写好，拿到观测点即可直接跑。

## 8. 对 Tessera 的裁决

| spec 条目 | 原判 | 按本边界 |
|---|---|---|
| §14 流量形状 | "当前最大缺口，可能致命" | **接受暴露**（依据 §3.1 + §3.4）。路径 A / B 均不必为它实施 |
| §13 时序缓解 | "v1 必须实现，含每连接现场测量 front" | **降级**。时序旁路要求对手已定向观测该 IP。v1 只做预热连接池 + 存档采样；现场测量的代价（每认证连接一次外拨）反而加速 front 拒绝我们 |
| §5 L1（QUIC 指纹） | ⚠️ 待补 | **❌ 升级为现役能力正对着的破绽**（§1.4） |
| §5 L4（SNI/IP 不匹配） | "无解，靠 P2 兜底" | 改写为**有参照数的赌注**（§3.5）。P2 兜不住 L4——L4 描述的审查者根本不探测 |
| front 判据 | "真实、可达、流量大、TLS 1.3" | **第一判据改为「名字不在国家级 + 目标省级 SNI 黑名单」**（§1.3 / §1.5），零容错。流量类别退居次要 |
| 端口 | 隐含 443 | 需**非 443 回落**（§5） |
| 节点 IP 生命周期 | 不在设计内 | **应进入设计**，且优先级高于协议层改进，直至 §4.1 被我们自己的日志裁决 |
