# k2p End-to-End Design — URL, Signal Server, Home, Away, Security

## Overview

k2p enables users to run a "k2s at home" — a proxy node behind NAT, discoverable via a signal server, reachable via hole punching (direct) or relay (fallback). The data plane is k2v5 (QUIC + k2cc). k2s acts as the signal/relay server but is zero-trust: it cannot read traffic or impersonate peers.

## Roles

| Role | What it is | Analogy |
|------|-----------|---------|
| **Home** | Node behind NAT, runs ProxyHandler, serves traffic to its LAN | A k2s behind NAT |
| **Away** | Client connecting to Home from anywhere | A k2 client |
| **k2s** | Signal server + stub relay, zero-trust | Tailscale DERP |

## k2p URL Format

```
k2p://home-abc:PEER_SECRET@home-abc.proxy.kaitu.io:443?pin=sha256:xxxx&ip=1.1.1.1&ip6=xxxx&ech=xxxx&fp=chrome
      ────────  ───────────  ──────────────────────────  ─────────────  ─────────────────────────────────────
      UDID      peer secret  signal server (UDID prefix)  Home cert pin  inherited from k2v5 (k2s params)
```

### Fields

| Field | Source | Purpose |
|-------|--------|---------|
| `home-abc` | userinfo username | Home's UDID |
| `PEER_SECRET` | userinfo password | Peer auth (Home generates, k2s never sees) |
| `home-abc.proxy.kaitu.io` | host | Signal server domain (UDID as subdomain prefix) |
| `443` | port | k2s port (signal + relay) |
| `pin=sha256:xxxx` | query | Home's TLS cert pin (Away verifies Home identity) |
| `ip=1.1.1.1` | query | k2s IP (skip DNS, same as k2v5) |
| `ip6=xxxx` | query | k2s IPv6 (same as k2v5) |
| `ech=xxxx` | query | k2s ECH config (for signal/relay connection to k2s) |
| `fp=chrome` | query | TLS fingerprint (for signal/relay connection to k2s) |

### Parsing

`k2p.ParseURL(raw string) (k2p.Config, error)` extracts:
- `Config.HomeUDID` = username
- `Config.PeerSecret` = password
- `Config.SignalServer` = `https://{host}:{port}` (strip UDID prefix from domain to get k2s base domain)
- `Config.Pin` = pin query param
- `Config.WireCfg` = wire.Config populated from ip/ip6/ech/fp/port (same parsing as k2v5)

### URL Generation

Home generates the URL locally during `k2 peer setup`:
1. Parse the k2v5 URL (to get k2s host, ip, ech, fp params)
2. Generate TLS cert pair → compute pin hash
3. Prompt user for password (= PEER_SECRET)
4. Register UDID with k2s signal server (sends UDID + STUN address, NOT secret or pin)
5. Assemble k2p URL: `k2p://{udid}:{secret}@{udid}.{k2s-host}:{port}?pin={hash}&{k2v5-params}`

## Signal Server (`signal/` package)

Independent package, zero external dependencies beyond stdlib + gorilla/websocket.

### Store

```go
// signal/store.go
type PeerEntry struct {
    UDID      string
    Addr      string       // STUN-discovered public UDP address
    NATType   string       // "easy", "hard", "open"
    Networks  []string     // Home's LAN CIDRs (e.g. ["192.168.1.0/24"])
    DNS       string       // Home's LAN DNS server
    UpdatedAt time.Time
    ws        *websocket.Conn // push channel (nil if disconnected)
}

type Store struct {
    mu    sync.RWMutex
    peers map[string]*PeerEntry // UDID → entry
}
```

k2s does NOT store: peer secret, pin hash, TLS private key. These never leave Home.

### HTTP+WS Endpoints

All endpoints require the UDID in the path for routing. No auth on signal endpoints — UDID is public, sensitive data (secret/pin) never passes through signal.

| Method | Path | Purpose | Auth |
|--------|------|---------|------|
| `POST` | `/k2p/register` | Home registers/updates address | UDID in body (no secret) |
| `GET` | `/k2p/lookup/{udid}` | Away queries Home's info | None (UDID is public) |
| `POST` | `/k2p/connect` | Away signals punch request → WS push to Home | None |
| `GET` | `/k2p/ws?udid={udid}` | Home persistent WS for notifications | UDID in query |

### Register Request/Response

```json
// POST /k2p/register
{
    "udid": "home-abc",
    "addr": "1.2.3.4:58231",
    "nat_type": "easy",
    "networks": ["192.168.1.0/24"],
    "dns": "192.168.1.1"
}
// Response: 200 OK
```

### Lookup Response

```json
// GET /k2p/lookup/home-abc
{
    "udid": "home-abc",
    "addr": "1.2.3.4:58231",
    "nat_type": "easy",
    "networks": ["192.168.1.0/24"],
    "dns": "192.168.1.1",
    "online": true
}
```

### Connect Request (triggers WS push)

```json
// POST /k2p/connect
{
    "home_udid": "home-abc",
    "away_addr": "5.6.7.8:9012",
    "nat_type": "easy"
}
// Response: 200 OK (k2s pushes PunchNotify to Home's WS)
```

### Stub Relay

When punch fails, Away and Home fall back to relaying through the signal server's WebSocket connections. Both are already connected (Home via persistent WS, Away opens WS for relay).

```
Away WS ←→ k2s relay ←→ Home WS
           (dumb pipe: forward bytes, no decrypt)
```

The relay forwards opaque bytes. The inner QUIC (Away↔Home, using Home's TLS cert) runs on top of the WS byte stream. k2s sees only encrypted bytes.

Relay protocol on WS:
- Message type `"relay"`: `{"type": "relay", "data": "<base64 UDP packet>"}`
- k2s matches Away↔Home by UDID, forwards `data` field

Performance is not optimal (base64 + WS framing overhead) but functionally complete. Future optimization: dedicated UDP relay port with TURN-like protocol.

## Home Side

### `k2 peer setup`

```
$ k2 peer setup k2v5://user:pass@proxy.kaitu.io:443?ech=xxx&ip=1.1.1.1
  请设置 peer 密码: ********

  ✓ 生成 TLS 证书 (EC P-256)
  ✓ 注册到 proxy.kaitu.io
  ✓ 检测内网: 192.168.1.0/24, DNS: 192.168.1.1

  你的 k2p 链接:
  k2p://home-abc:PASSWORD@home-abc.proxy.kaitu.io:443?pin=sha256:xxxx&ip=1.1.1.1&ech=xxx

  把这个链接发给需要访问你家网络的人。
```

Steps:
1. Parse k2v5 URL → get k2s params
2. Generate UDID (random or user-specified)
3. Prompt password → PEER_SECRET
4. `wire.GenerateCertPair()` → TLS cert + pin hash
5. Detect local networks (enumerate interfaces, filter private CIDRs)
6. Register with k2s signal: POST /k2p/register {udid, addr, nat_type, networks, dns}
7. Print k2p URL

### `k2 peer run`

Home daemon mode — stays online, accepts connections:

```
$ k2 peer run k2v5://user:pass@proxy.kaitu.io:443?ech=xxx&ip=1.1.1.1
```

Flow:
1. Load saved config (UDID, cert, peer secret)
2. STUN probe → discover public address
3. Register with k2s signal
4. Open WS to k2s for notifications
5. Keepalive loop (re-STUN + re-register every 25s)
6. On PunchNotify: punch → QUIC listen → run ProxyHandler

ProxyHandler config:
- `AllowPrivateIP = true` (Home's LAN is the target)
- Peer auth: verify PEER_SECRET from Away before accepting streams

## Away Side

### Connection Flow

```
Away parses k2p URL
  │
  ├── 1. Extract signal server from URL (strip UDID prefix from host)
  ├── 2. Lookup Home: GET /k2p/lookup/{udid}
  │      → gets: addr, nat_type, networks, dns
  ├── 3. STUN probe → classify own NAT
  ├── 4. Signal connect: POST /k2p/connect {away_addr, nat_type}
  ├── 5. Punch (standard or birthday based on NAT types)
  │      ├── success → QUIC dial to Home (verify pin, send peer secret)
  │      └── fail → relay fallback via k2s WS
  ├── 6. Peer auth: send PEER_SECRET, Home verifies
  ├── 7. Auto-configure routes: networks from lookup → k2p Dialer
  └── 8. Auto-configure DNS: dns from lookup → k2p DNS upstream
```

### Auto-configuration

Away receives `networks` and `dns` from lookup. Engine auto-configures:
- Route Home's CIDRs through k2p Dialer (like k2rule.SetTmpRule but for CIDRs)
- DNS queries for Home's LAN domains through Home's DNS server

User experience: connect with one URL, access everything on Home's network immediately.

## Security Model

### Trust Boundaries

```
                    ┌─────────────────┐
                    │ k2s (zero trust)│
                    │ Knows: UDID,    │
                    │   Home addr,    │
                    │   NAT type,     │
                    │   networks      │
                    │ Cannot: decrypt,│
                    │   impersonate,  │
                    │   inject        │
                    └────────┬────────┘
                             │ signal + relay (encrypted bytes only)
              ┌──────────────┴──────────────┐
              │                             │
         ┌────┴────┐                   ┌────┴────┐
         │  Home   │                   │  Away   │
         │ Knows:  │ ←── e2e QUIC ──→ │ Knows:  │
         │  privkey│   (Home TLS cert) │  pin    │
         │  secret │                   │  secret │
         └─────────┘                   └─────────┘
```

### Credential Separation

| Credential | Home | Away | k2s | Purpose |
|-----------|------|------|-----|---------|
| UDID | ✅ | ✅ | ✅ | Signal routing |
| PEER_SECRET | ✅ | ✅ | ❌ | Peer authentication |
| TLS private key | ✅ | ❌ | ❌ | TLS handshake |
| pin (cert hash) | ✅ | ✅ | ❌ | Verify Home identity |
| Home address | ✅ | via signal | ✅ | Punch/relay target |

### Attack Resistance

| Attack | Prevented by |
|--------|-------------|
| k2s reads traffic | End-to-end QUIC encryption (Home's TLS cert) |
| k2s impersonates Home | Away verifies pin (cert hash) |
| k2s impersonates Away | Home verifies PEER_SECRET (k2s doesn't know it) |
| k2s injects traffic | Cannot forge inner QUIC packets (no TLS session key) |
| Third party connects to Home | Must know PEER_SECRET + pass pin verification |
| MITM on punch path | QUIC TLS handshake + pin verification |

## Config Changes

### k2p.Config (updated)

```go
type Config struct {
    HomeUDID     string
    PeerSecret   string           // Home-Away shared secret (never sent to k2s)
    SignalServer string           // k2s base URL (https://proxy.kaitu.io:443)
    Pin          string           // Home's cert pin (sha256:xxxx)
    WireCfg      wire.Config      // inherited k2v5 params (ech, ip, fp, port)
    TLSCert      *tls.Certificate // Home's TLS cert (Home side only)
    TicketStore  *wire.TicketStore
    DirectDialer wire.DirectDialer
    STUNServers  []string
    Networks     []string         // Home's LAN CIDRs (from signal lookup)
    DNS          string           // Home's LAN DNS (from signal lookup)
}
```
