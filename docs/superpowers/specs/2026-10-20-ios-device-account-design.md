# 开途 iOS：设备账号（免登录开始试用 / 订阅）— 设计

日期：2026-10-20 · 状态：草稿（多设备规则、本机证明方式已由 David 定），待 David 整体确认 · 关联：`2026-10-19-kaitu-ios-apple-trial-design.md`（试用）、`2026-10-20-social-sign-in-design.md`（Apple / Google 登录）

## 1. 为什么做

- 开途 App 10-09 ~ 10-19：首次打开 971 → 登录 430（**流失 56%，最大的一个漏口**）→ 连上 45。iOS 占登录的 91%。
- 现在 iOS 购买前必须邮箱验证码登录（`webapp/src/components/IosSubscribePanel.tsx:16-17,283`）。收不到验证码、嫌麻烦的人在这一步就走了。
- Apple 审核 5.1.1：购买非账号类内容不得强制注册；注册须可选，用途是"在其他设备上使用"。我们现在的做法本身就有被拒风险。
- David（2026-10-20）：试用不和账号挂钩，只在当前设备起作用，不要邮箱；要用其他设备时再引导设邮箱 / Apple 登录，之后才能用满 5 台。

成功标准：iOS 新用户不输入任何东西即可点「免费试用」；「首次打开 → 开始试用 / 订阅」不再经过登录；重装不丢会员；要换手机 / 加设备的人在【我的】→【其他设备登录】被引导绑定邮箱。

## 2. 目标 / 非目标 / 反目标

**目标**
- 开途 iOS 首次打开、未登录时，自动建一个**设备账号**（没有邮箱、没有任何登录身份），直接可试用 / 订阅。
- 设备账号只能在这一台设备上用（设备上限 = 1）。绑定邮箱或 Apple / Google 登录后变成普通账号，设备上限恢复套餐值（5 台）。绑定是**在原账号上补身份**，订阅和时长不动。
- 重装 App 回到同一个设备账号。
- 换手机 / 加设备：在原设备【我的】→【其他设备登录】绑定邮箱（或 Apple 登录），新设备用它登录。不做「凭 Apple 购买记录跨设备接管设备账号」。
- 「已有账号？登录」入口始终可见，老用户照旧登录。

**非目标**
- 安卓 / 桌面 / 网页 / 路由器：照旧先登录。
- Overleap：本期不开（品牌开关默认关，以后单独决定）。
- 账号合并工具（设备账号与已有邮箱账号合并时长）——见 §4.4 冲突规则。
- 给设备账号发邮件（没有邮箱；Apple 自己发收据和续订通知）。

**反目标**
- 已登录用户的任何行为变化。
- 付费设备账号因为卸载、或在这台设备上登录别的账号而「丢了」。
- 一个设备账号同时在第二台设备上可用（试用尤其不行）。
- 漏斗里「登录」一步消失后看不出转化（要有替代事件）。

## 3. 现状（2026-10-20 摸底）

- **udid**：webapp 随机 UUID → sha256 截 16 字节（`webapp/src/services/device-udid.ts:20-42`），存在 App 私有 JSON 文件（`capacitor-storage.ts`，不进 iCloud 备份）。**卸载即丢**；新 udid 生成时清掉 token（`device-udid.ts:44`）。没有任何 Keychain 代码。
- **token**：同一个存储（`auth-service.ts:32,154-159`），卸载即丢。
- **设备**：`Device.UDID` 唯一、`UserID` 非空（`api/model.go:162-190`），一台设备只属于一个用户。邮箱登录时若该 udid 属于别人，删旧设备行并给旧主人发邮件（`api/api_auth.go:257-282`），设备上限踢最旧（`logic_auth.go:510`）。
- **身份**：`User` 没有 email 列，身份全在 `LoginIdentify`（`model.go:145-159`）。零身份的用户在库层面合法。发邮件遇到无邮箱用户软失败（`logic_email.go:265-271`，调用方只记日志）。后台若干视图以 `len(LoginIdentifies)>0` 兜底；`lookup_user` 只能按 UUID 找到无邮箱用户。
- **购买**：`appAccountToken = uuidv5(ns, user.UUID)`（`logic_apple_iap.go:35-43`），首笔绑定时服务端校验不符即拒（`:159-168`）——设备账号天然适配，只要有 user UUID。
- **绑邮箱**：`POST /api/user/email/update-email`（`api_user.go:87-196`）对无邮箱用户会新建 email 身份——已可用；邮箱已属别的账号时报 `ErrorEmailAlreadyInUse`。
- **Apple / Google 绑定**：社交登录那边的 `/api/user/social/bind`（AuthRequired + EnforceDeviceClass）已确认支持零身份用户；可信邮箱未被占用时同一事务补 email 身份行；冲突返回 `409002 ErrorSocialIdentityTaken` / `409003 ErrorSocialProviderAlreadyBound`。
- **漏斗**：App 路线「登录」一步 = `auth_done`（`logic_funnel_paths.go:165`）。

## 4. 设计

### 4.1 本机证明 = 设备 ID（David 2026-10-20 定）

「本机证明用本地存储的唯一标识，即我们现有的设备 ID 体系；不可能有第二台设备可以试用。」

- 设备 ID 就是现有的 udid。改动只有一处：**存进 iOS Keychain**，可访问性 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`——卸载重装后还在，不随 iCloud 钥匙串同步到别的设备，所以设备 ID 离不开这台手机。
- 生成顺序：先读 Keychain；没有时**先把现有存储里的 udid 迁进 Keychain**（老用户升级新壳不能换 udid——换 udid 会触发 `clearStaleAuthTokens` 把所有 iOS 用户登出）；两处都没有才随机生成并写入。
- K2Plugin 新增 `secureGet / secureSet`（iOS Keychain；Android/桌面不实现，webapp 按能力探测）。属于原生能力 → 随第 ② 步的新 iOS 版本发布，bump `BRIDGE_API_VERSION`。旧壳行为不变。

### 4.2 接口

只加一个：`POST /api/auth/device-account`，无鉴权，body `{udid, remark, language, platform}`。

| 该 udid 的现状 | 结果 |
|---|---|
| 库里没有这个设备 | 建 User（零身份）+ Device，返回 `DataAuthResult` |
| 设备行属于一个**零身份**用户（即重装后回来） | 给该用户签发新 token（不新建） |
| 设备行属于**有身份**的用户 | 拒绝，返回「请登录」错误码 |
| 品牌开关关闭 | 返回明确错误码 |

- 一个设备账号永远只有建它的那一个 udid——设备上限 1（§4.3）+ udid 不出这台手机，所以不会有第二台设备能用这个试用或订阅。
- 已知取舍：udid 本身不是秘密（它和 token 一起出现在节点连接 URL 里），知道某台设备 udid 的人理论上能调这个接口登进那个零身份账号。按 David 定的方案不额外加密钥；加固见文末「可选项」。
- 限流：按 IP 限流（builder 定阈值）；零身份、未试用未付费的设备账号连不了任何节点，批量注册拿不到免费服务，主要防库膨胀。
- 后台清理：本期不做（我的判断：按现在每 10 天约 1000 次首次打开，空账号行的量可以忽略；以后量大再加）。

### 4.3 设备上限与绑定

- `checkDeviceLimitOrKick`：用户零身份时上限 = 1。
- 绑定（邮箱验证码 / Apple / Google）成功 = 在当前用户上补 `LoginIdentify` 行；之后上限按套餐，用户可在别的设备用该身份登录。
- 绑定入口：**【我的】→【其他设备登录】**（David 定）。
  - 已绑定：显示「在其他设备上用 {脱敏邮箱} / Apple 登录即可，最多 {N} 台」。
  - 未绑定：说明「设置邮箱后，可在最多 5 台设备上使用」，直接进入绑定邮箱流程（Apple / Google 绑定随社交登录上线后同屏出现）。
  - 设备管理页、设备上限被拒时也跳到这里。
- 绑定后这台设备照常用现有 token；重装后 `/device-account` 返回「请登录」，走普通登录。
- 另一台设备上点「恢复购买」而交易属于未绑定的设备账号：服务端照旧拒绝（appAccountToken 不符），客户端提示「这个订阅属于另一台设备，请在那台设备的【我的】→【其他设备登录】设置邮箱，再在这里用邮箱登录」。

### 4.4 冲突规则（我的判断）

| 情况 | 处理 |
|---|---|
| 设备账号**没有**任何订阅 / 试用记录，用户选择登录已有邮箱账号 | 直接登录已有账号，设备账号丢弃（设备行转给已有账号，按现有登录流程） |
| 设备账号**有**订阅或试用，用户要绑定的邮箱 / Apple ID 已属别的账号 | 拒绝绑定，提示「该邮箱已有账号，请换一个邮箱绑定；如需合并请联系客服」。不做自动合并（Apple 交易已永久绑定设备账号的 appAccountToken，合并要搬订阅链，风险大于收益） |
| 设备账号有订阅或试用，用户在这台设备上点「登录已有账号」 | 先引导绑定邮箱（MUI 对话框：「这台设备上的会员属于当前账号，请先设置邮箱，否则登录别的账号后无法找回」），绑定后再登录；用户坚持跳过则照常登录（设备账号的订阅从此只能找客服） |
| 零身份用户点「退出登录」 | 不提供普通退出：该位置换成【其他设备登录】和「登录其他账号」（后者走上一行）。服务端 `api_logout` 对零身份用户**不删设备行**（现在会删，`api_auth.go:491`）——否则 udid 找不回账号，重装即丢会员 |
| 邮箱登录时 udid 属于一个设备账号（现有的「设备转移」邮件） | 设备账号无邮箱，跳过发邮件（现在本就软失败，改为显式跳过、不记错误日志） |

### 4.6 客户端（webapp）

- 启动时：iOS + 开途 + 有 `secureGet` 能力 + 未登录 → `/device-account`（新建或重装回来）；返回「请登录」或失败 → 退回现在的登录界面（不阻塞）。
- 付费页 / 试用面板：设备账号视为已登录，不再显示内嵌 `EmailLoginForm`，订阅按钮直接可点。顶部保留「已有账号？登录」。
- 【我的】：零身份时显示「这台设备专用」+【其他设备登录】入口（§4.3）。
- 账号相关页面（设置、设备管理）在零身份时隐藏邮箱相关项，显示绑定入口。
- 旧壳（无 `secureGet`）：行为完全不变（仍需登录）。

### 4.6.1 客服

- 零身份用户提工单时表单要求填一个联系邮箱（只用于回复，不绑定为登录身份）；`api_ticket.go` 读用户邮箱失败时用这个。
- 【我的】/ 设置页显示可复制的用户 ID（UUID），客服用现有 `lookup_user` 按 UUID 查（不加前缀搜索）。
- 现状：零身份用户现在**提不了工单**（`api_ticket.go:43-49` 取不到邮箱直接 500），必须修。

### 4.7 漏斗

- 新事件 `device_account_created`、`identity_bound` 由**服务端**在建号 / 首次补身份成功时写入（`funnelEnqueue`）。现有 `signup` 事实按 `users.created_at` 推导，设备账号建号时自动计入，不用改；App 路线中「登录」一步对开途 iOS 新壳改为「建号或登录」（`device_account_created ∪ auth_done`）。`identity_bound` 不放进激活路线（放在末尾会改变路线「完成」人数的含义——安卓/桌面/邮箱登录的人永远不会触发它），单独按事件看绑定率。
- `auth_done` 语义不变（真实身份登录）。

### 4.8 品牌开关

- `brandRegistry` 加 `DeviceAccount bool`（开途 true，Overleap false），经 App 配置接口下发；客户端以服务端开关为准。改品牌数据后重生成 `contracts/api-contract.json`。

### 4.9 发布门（我的判断）

- 绑定方式第一版只要求邮箱（接口已有）；Apple / Google 绑定随社交登录那边上线，不互相阻塞。

## 5. 与其他工作的关系

- **试用 spec**：设备账号是试用的入口；试用期 = 设备账号 + 体验线路；转正走 §3.9 升级。两者都随第 ② 步 iOS 版本发布。
- **社交登录**：已与该会话对齐（见 §3）。
- 发布顺序：API（开关默认关）→ iOS 新版（含 Keychain、试用、设备账号）提审 → 过审后打开开途开关 + ASC 试用。

## 6. 测试

- API（DB 真跑 0 SKIP）：`/device-account` 四种 udid 现状、上限 1、绑定后上限恢复、绑定冲突、无邮箱跳过转移邮件、零身份登出不删设备行、零身份提工单、恢复购买属于别的账号返回 409004。
- webapp：启动分支矩阵（有 / 无能力 × Keychain 有 / 无 udid × 已登录）、udid 迁移不换值、付费页不显示内嵌登录、旧壳不变。
- 真机 smoke：首次打开 → 试用 → 卸载重装仍是同一账号 → 【其他设备登录】绑邮箱 → 另一台设备登录；未绑定时第二台 iPhone 同 Apple ID 恢复购买 → 看到引导提示。

## 7. 留给 builder

- 限流阈值、清理 worker 周期。
- 新错误码：`403004` 本品牌未开设备账号、`403005` 该设备已属有身份账号请登录、`409004` 这个 Apple 订阅属于另一个账号（409002/409003 已被社交登录占用）。同步 `errorCatalog.ts` 与全部语言。
- Keychain 封装细节。

## 已定：同一 Apple ID 的多台设备（David 2026-10-20）

「付费后要多台设备，必须登录我们的账号；同一个账号才能共享 5 台。不登录，账号系统就不分那 5 台。」

- 零身份设备账号**无论试用还是付费，上限都是 1 台**，同一 Apple ID 也不例外。
- 引导统一在【我的】→【其他设备登录】（§4.3）。
- 已知风险：没绑定邮箱、原手机丢失的用户，订阅只能找客服。Apple 审核 3.1.2（订阅应在用户的设备上可用）可能被问到，答复口径：「用户可随时在 App 内设置邮箱，在其他设备上使用」。

## 可选项（不做，除非 David 要）

- 建号时额外签发一个设备密钥，与 udid 一起存 Keychain，重装回来时校验——堵住「知道 udid 就能登进零身份账号」。
