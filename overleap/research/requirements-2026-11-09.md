# DePIN 全球住宅 IP 代理网络项目推进与调研方案

## 一、 项目推进阶段与核心事项

### 阶段一：项目前期规划与可行性验证（0-1阶段）

* **事项 1：业务逻辑与经济模型设计**。明确“宽带提供方（Host）”和“网络使用方（Client）”的双边收益与成本模型。确认 30%-50% 平台抽佣的具体资金流向（中心服务器带宽、STUN/TURN 打洞成本、客服团队、硬件补贴等）。
* **事项 2：核心痛点与高频场景梳理**。除“跨国访问政府资料”外，锚定其他高溢价需求场景（如跨国流媒体解锁、跨境电商防关联运营、海外银行账户本地化维护）。
* **事项 3：启动综合调研课题**。开展针对市场规模、各国法律合规、定价策略的专项深度调研（详见下文第二部分）。

### 阶段二：软硬件研发与安全架构搭建

* **事项 1：硬件供应链锁定**。确认成本在 150-200 元人民币的 Linux 硬件方案（如低功耗 ARM 盒子或轻量级 x86 设备），确保满足 7x24 小时低功耗稳定运行的要求。
* **事项 2：边缘节点系统（OS）定制**。开发并烧录精简版 Linux 固件，部署网络隧道守护进程，实现开机自启、断线重连、配置自动下发及远程 OTA 升级。
* **事项 3：【核心新增】加密 KYC 与委员会审计系统开发**。
* 开发非对称加密的身份认证模块。需求端（Client）提交的实名信息在本地直接加密，密文上传至服务器。
* 建立多重签名的“总密钥”管理系统。平台不保留直接解密权限，解密私钥由“审查委员会”共同持有（或采用门限签名技术分片保管）。



### 阶段三：商业模式落地与平台基建

* **事项 1：定价与产品化封装**。将硬件终端定价在 300-400 元，对外包装为“提供企业级售后维护与稳定收益保障”的智能边缘网络设备，并建立 150-200 元差价的售后服务准备金池。
* **事项 2：审查委员会制度建立与章程起草**。明确委员会的构成（如法律顾问、社区代表、核心团队）、触发 KYC 解密的条件（如收到特定国家执法机构的正式协查通报），以及投票表决流程。
* **事项 3：支付与跨境结算对接**。搭建 Client 端的付费订阅通道，以及 Host 端的收益提现通道（需解决跨国微支付的高昂手续费问题）。

### 阶段四：冷启动与市场推广

* **事项 1：种子节点（Host）重资产铺设**。自营冷启动，团队初期在核心目标国家（如英国、美国）寻找亲友或租赁真实住宅预先铺设一批节点，建立官方底座池，打破双边市场“先有鸡还是先有蛋”的死结。
* **事项 2：需求端（Client）精准获客**。面向海外华人、数字游民社区精准投放，主打“纯净真实家庭住宅 IP + 绝对隐私保护”的核心卖点。

## 二、 综合调研课题：全球住宅 IP 共享网络的合规化与商业可行性评估

**课题背景**：本项目旨在构建连接全球闲置家庭宽带与异地网络需求的 P2P 网络，并在商业模式中引入了创新性的“加密 KYC 委员会”机制以规避法律风险。
**核心调研维度**：

1. **全球法律合规与责任阻断 (Legal & Compliance)**
* **ISP 协议限制**：调研目标国家（如英国、泰国）主流运营商的服务条款（TOS）中对“宽带分享/转售”的具体惩罚措施及实际执行力度。
* **避风港适用性**：调研平台方引入“加密 KYC 委员会审查制”后，能否在当地法律（如欧盟 GDPR、英国 Online Safety Act）下实现平台、Host、Client 三方的责任隔离，最大程度保护 Host 免受 Client 违规行为的连带责任。


2. **市场规模与竞争护城河 (TAM & Competitive Moat)**
* **替代品定价**：调研现有商业化住宅代理（如 Luminati/Oxylabs）的零售定价与目标客户群。
* **壁垒分析**：对比现有去中心化 VPN（如 Mysterium），评估我们通过“纯硬件盒子方案 + 高质量售后维保”建立的物理与服务双重壁垒。


3. **硬件定价与回本周期模型 (Pricing & ROI)**
* 推演在 30%-50% 抽佣下，售价 300-400 元的硬件需要多少有效流量才能让 Host 在 3-6 个月内收回成本，并测算该回本周期对 C 端用户加盟意愿的影响。

## 三、 补充思考点（深度风险与技术建议）

你的“加密 KYC + 委员会审查”的设计非常惊艳。它完美解决了一个核心矛盾：**既不能做无门槛的法外之地（保护 Host 不背锅），又不能让用户觉得隐私被平台随意监控（保护 Client 隐私）**。针对这个机制和整体架构，你需要补充考虑以下几点：

**1. KYC 委员会的响应时效与“冻结机制”**
如果 Client 真的进行了严重的违法操作，执法机构找上 Host，Host 会立刻面临压力。此时如果委员会投票解密流程需要 3-5 天，Host 可能会直接崩溃并拔掉设备。

* **建议**：在系统中加入“一键紧急熔断/冻结”功能。当 Host 遇到合规风险投诉时，可以立刻熔断该连接，并将对应的 Client 账号暂时冻结。解密 KYC 可以慢慢走委员会投票流程，但“阻断危害继续发生”的动作必须是实时的。

**2. 流量白名单/分流机制 (Split Tunneling) 的必要性**
仅靠事后的 KYC 追责仍然是被动的。如果 Client 用英国 Host 的网络去下载盗版 BT 电影或者访问暗网，依然会给 Host 带来巨大的麻烦。

* **建议**：结合你的初衷（访问政府资料），设备端应当默认开启**策略路由**。即：只有访问正常网站（如政府域名、银行、常规流媒体等白名单/灰名单流量）时，才通过 Host 的节点转发；如果是 P2P 种子下载、高风险端口流量，直接在 Client 本地网络截断或走常规通道。这能在物理层面上将 Host 的风险降到最低。

**3. 家庭网络 NAT 穿透的技术成本**
绝大多数全球家庭宽带处于大内网（CGNAT）中，没有公网 IP。150 块钱的 Linux 盒子放在 Host 路由器的最内层，Client 是无法直接连接它的。

* **建议**：你的中心化平台必须承担 STUN/TURN 打洞服务器的角色，或者部署边缘中继节点（Relay）。如果打洞失败，流量就要走你的中继服务器转发，这会产生不小的中心化带宽成本，在规划那 30%-50% 的抽佣资金使用时，必须把中继带宽成本单独留出来。
